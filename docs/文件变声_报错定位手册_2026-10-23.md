## 2. 这一轮真找到一个崩溃并修掉

```
TclError: wrong # coordinates: expected at least 4, got 2
  at spectrum.py:582  QuadScope.draw()
  via  host_app.py:_show_file_spectrum → _load_file
```

- **触发条件**：四路波形里任意一路只有 **1 个点** —— 极短素材，或面板还没完成布局
  （`gw` 太小）时。
- **表现**：点"载入文件"当场抛异常。原来是 Tk 回调里的异常，窗口版 EXE 没有控制台，
  用户只看到"卡一下 / 没反应 / 一个没有上下文的框"。
- **修法**：`len(pts) < 2` 就跳过这一帧的绘制（`spectrum.py`，三处）。

## 3. 为什么"重启"解决不了（按三类原因逐一核对）

| 猜测 | 本程序实际情况 | 结论 |
|---|---|---|
| 配置未生效 | 程序**没有任何配置文件**：不读写 ini/json/注册表，每次启动都从零枚举设备 | 不存在这条路；改配置也修不了 |
| 缓存/持久化残留 | 程序不写任何缓存目录（10-23 之前一个都不写）。跨进程留存的只有**输出文件本身**、Windows 的**音频端点/串口分配** | 文件变声这条路上**没有设备参与**，所以重启清不到东西 |
| 依赖/环境问题 | exe 自带 `sounddevice 0.5.6` / `soundfile` / `av`（自检里逐项 PASS），不依赖系统 Python | 不是环境问题 |

**关键**：`重启` 只能清"设备/驱动/串口"这类内核态状态，而**文件变声全程不碰设备**。
所以只要报错发生在文件变声，"重启"本来就不可能有用 —— 这条要先讲清楚，能省掉一轮无效尝试。

顺带：`HiberbootEnabled=1` 时，用**关机→开机**并不能重置内核状态。
真要重置，用 开始菜单→**重启**，或命令行 `shutdown /r /t 0`。

## 5. 下次报错的 30 秒排查流程

1. **看日志**（10-23 新增，窗口版 EXE 也能看）：
   ```
   %LOCALAPPDATA%\ACX720VoiceChanger\logs\app-YYYYMMDD.log
   ```
   第一行就是"运行方式：打包 EXE（构建于 …）"或"源码（最新改动 …）"。
   对话框的标题+正文也会以 `DIALOG[showerror] …` 的形式落在这里。
2. **要复现某个文件**（不点界面）：
   ```
   python tool/probe_file_mode.py --src "C:\路径\素材.flac"
   ```
   它会跑真实 App 的载入+处理，最后打印界面日志和弹过的对话框。
3. **怀疑是某类格式**：
   ```
   python tool/probe_file_formats.py
   ```
   14 类用例一张表，❌ 那格就是问题所在。
4. **怀疑是旧包/旧代码**：比对时间戳
   ```
   dir host\*.py            → 源码最后修改时间
   dir dist\ACX720VoiceChanger\ACX720VoiceChanger.exe
   ```
   exe 必须比所有 `host\*.py` 都新；否则重新打包。

# 附录：`PermissionError(13)` 现场复现（2026-10-23 10:43）

用户的报错原文（截图）：

```
处理失败
PermissionError(13, 'Permission denied')
输出：C:/Users/Administrator/Downloads/老狼&王婧_想把我唱给你听_变声.wav
（若是 Permission denied：关掉占用该文件的播放器/QQ，或换一个输出目录再试）
```

## 关键证据：同一个 exe、同一个账号，写权限却不一样

用 `ACX720VoiceChanger.exe --diag` 在**打包版进程**里逐目录试写，结果：

```
frozen            = True
 桌面       FAIL    C:/Users/Administrator/Desktop    → PermissionError(13, 'Permission denied')
 下载       FAIL    C:/Users/Administrator/Downloads  → PermissionError(13, 'Permission denied')
 文档       FAIL    C:/Users/Administrator/Documents  → PermissionError(13, 'Permission denied')
 音乐       FAIL    C:/Users/Administrator/Music      → PermissionError(13, 'Permission denied')
 程序目录   OK      …\ACX720VoiceChanger              （写入 1024 字节）
 日志目录   FAIL    C:/Users/Administrator/AppData/Local/ACX720VoiceChanger/logs
 走真实写盘函数 audio_io.save_audio → FAIL  PermissionError(13)
```

而**同一台机器、同一个账号**，用 `python.exe` 往完全相同的路径写 1 秒静音：

```
下载  OK   C:/Users/Administrator/Downloads/_acx720_diag_xxxxx.wav（176444 字节）
```

⇒ 结论：**这不是代码问题，也不是文件被别的程序占着**，而是
**这个 exe 进程没有用户目录的写权限**（受限令牌 / 沙箱 / 组策略）。
"关掉占用文件的播放器"那条提示在这种情况下是无效的 —— 换名字、换目录也全都会失败。

这也解释了为什么程序**连自己的日志都写不出来**：日志默认写
`%LOCALAPPDATA%\ACX720VoiceChanger\logs\`，同样被拒。

## 为什么重启没用

写权限是**进程启动时由令牌决定**的，不是系统状态。重启既不会改令牌，
也不会改目录 ACL —— 只要还用同样的方式启动，结果一模一样。
（另外这台机器 `HiberbootEnabled=1`、`LastBootUpTime=10-20 17:53`，
所谓"重启"多半只是休眠恢复。）

## 代码这边的处置（不再让用户拿到一句干巴巴的报错）

1. **写盘四级降级**（`_save_audio_retry`）：
   原路径 4 次重试 → 同目录换时间戳名 → `音乐\ACX720变声` → `%TEMP%\ACX720VoiceChanger`
   → `<程序目录>\输出`。任何一级成功都会在日志里写明**改存到哪了**。
2. **日志三处兜底**（`file_log`）：`%LOCALAPPDATA%` → `<程序目录>\logs` → `%TEMP%`，
   并把每个候选的成败写进日志头（`日志候选：…`）。
3. **启动自检一行**（`_writable_summary`）：进程写不了桌面/下载时，界面日志第一屏就写
   `⚠ 当前进程写不了：下载（PermissionError）… 输出会自动改存到程序目录的「输出」子文件夹`。
4. **`--diag` 自检命令**：把上面那张表打出来，写到 `<程序目录>\_diag.txt`。
   `dist\swap_new_build.bat` 换完包会自动跑它并弹记事本。
