# 外接 0.96" OLED 显示当前工作模式（2026-10-23）

> 目标：板子上的 0.96 寸 SSD1306（128×64，单色）实时显示**上位机界面里选的是什么**
> —— 变调还是分离、用的哪个引擎、变调多少、分离两路增益多少。
>
> 一句话方案：**上位机写 `tool/logs/mode.json` → 声卡桥把它转成 16 字节配置包塞进
> 串口 → STM32 用 USART2 旁听这路数据 → 刷新 OLED。** 音频通路（FPGA→SPI1→SPI2→DAC）
> 一个字节都没动。

---

## 1. 接线（4 根）

| OLED 引脚 | 接到 | 说明 |
|---|---|---|
| VCC | STM32 **3.3V** | 不要接 5V |
| GND | STM32 GND | 必须共地 |
| SCL | **PB6** | I2C1_SCL，400 kHz |
| SDA | **PB7** | I2C1_SDA |

再加一根**旁听线**（关键，否则屏幕只会显示 `WAIT HOST`）：

| 从 | 到 | 说明 |
|---|---|---|
| CH340 模块的 **TXD**（也就是接到 FPGA `uart_rx` 的那一根） | STM32 **PA3**（USART2_RX） | 一个 TX 带两个 RX，电气上完全没问题：FPGA 收音频帧，STM32 只挑里面的配置包 |

> 为什么不用 STM32 的 PA9/PA10：USART1(PA9) 是调试口，一直按 115200 打状态行；
> 而串口上跑的是 1.5 Mbaud。同一个 USART 只能有一个波特率，所以配置流走 USART2(PA3)，
> 调试口保持原样。
>
> 为什么不让 FPGA 转一手：那要改 RTL、重新综合、重新烧 bit，迭代一次十几分钟；
> 而 USART2 旁听只是**一根线 + 固件里几十行**，音频一个中断都不多。

```
上位机(界面)                    PC 侧                         板子侧
  │ 选模块/引擎/滑条
  ├─→ tool/logs/mode.json ──→ fpga_audio_bridge.py ──串口1.5M──┬─→ FPGA uart_rx（当噪声跳过）
  │        (300ms 轮询)              (夹在音频帧之间)            └─→ STM32 PA3(USART2)
  │                                                                    │
  └──────────────── 同一份参数也在算音频 ──────────────────────────────┤
                                                                       ↓
                                                              SSD1306 (PB6/PB7)
```

## 2. 屏幕长什么样（128×64，4 行 8×16 字符）

```
变调 · FPGA 直算                变调 · 小模型
┌────────────────────────┐     ┌────────────────────────┐
│ACX720            LINK │     │ACX720            LINK │
│变调 1.297x            │     │变调 0.609x            │
│FPGA SEMI+4.6          │     │MODEL SEMI-3.2         │
│DPH+19   G+0dB         │     │DPH-25   G-6dB         │
└────────────────────────┘     └────────────────────────┘

分离 · 本地模型(demucs)         分离 · 中置提取
┌────────────────────────┐     ┌────────────────────────┐
│ACX720            LINK │     │ACX720            LINK │
│分离 LOCAL             │     │分离 CENTER            │
│VOC70%  ACC100%        │     │VOC100%  ACC55%        │
│GAIN+3dB               │     │GAIN+0dB               │
└────────────────────────┘     └────────────────────────┘
```

- `LINK` = 3 秒内收到过配置包；断了就变 `--`，中间两行改成 `WAIT HOST`，一眼看出是线的问题。
- 第一行右边的 `LINK` 和左边 `ACX720` 都在第 0 页，`变调/分离` 用 16×16 汉字（字库自动生成）。
- 变调行 `1.297x` 就是板上 RTL 的 `1 + dphase/64`，和拨码档位对得上。
  半音 `SEMI+4.6` 是界面滑条的原始值，`DPH` 是换算到板上的 dphase。

不用接线也能先看版式：

```
python tool/preview_oled.py                 # 四种状态各出一张 PNG 到 tool/logs/
python tool/preview_oled.py --m pitch --e fpga_model --semi 7
```

## 3. 配置包协议（16 字节）

```
AA 55 | LEN | TYPE | payload[LEN] | CRC8
  LEN=11  TYPE=1（模式快照）
  CRC8: poly 0x07, init 0x00, 覆盖 LEN/TYPE/payload

payload：
  [0] mode     0=变调 1=分离
  [1] engine   0=FPGA 直算 1=中置提取 2=本地模型 3=FPGA 小模型
  [2] dphase   有符号，板上那套 (semi-5)*6 的等价量
  [3..4] semi10    半音×10，int16 小端
  [5..6] ratio1000 变调比×1000，uint16 小端
  [7] vocal_gain %   [8] acc_gain %
  [9] gain_db   有符号   [10] src 0=实时 1=文件
```

- **FPGA 不受影响**：它的帧状态机只在等 `A5 5A`，`AA 55` 会被当成噪声跳过。
  极端情况下包内恰好出现 `A5 5A`，那一帧 CRC 会失败、自动重新同步 —— 最多丢 2 帧（5 ms）。
- **STM32 不受影响**：USART2 用 DMA 环形缓冲 + IDLE 中断，每帧末尾才进一次中断
  （约 380 次/秒），不是逐字节中断 —— 逐字节的话 10 万次/秒的 CPU 开销会直接毁掉音频。
- 协议的唯一事实源是 `mcu/f103_spi_mcp4922/cfg_proto.h`，打包端与解析端靠
  `tool/verify_oled_cfg.py` 对表（8 项：字段一致性、负值、越界夹紧、CRC 错拒绝、截断拒绝、
  噪声前缀后能重新同步）。

## 4. 改了哪些文件

| 文件 | 改动 |
|---|---|
| `host/host_app.py` | 新增 `_publish_mode()`（在 `_poll` 里节流 300 ms）：把模块/引擎/半音/dphase/变调比/两路增益/总增益写进 `tool/logs/mode.json`（原子替换）。任何异常都吞掉，不影响变声 |
| `tool/fpga_audio_bridge.py` | 新增 `build_cfg_packet()` / `crc8()` / `_poll_cfg()`：mode.json 变了就在两帧音频之间插一个配置包，并留 3 ms 空闲让 STM32 的 IDLE 中断把它切成独立一段 |
| `mcu/.../cfg_proto.h` `.c`（新） | 协议 + 解析状态机（纯逻辑，可单测） |
| `mcu/.../oled.h` `.c`（新） | SSD1306 驱动：I2C1 400 kHz、页寻址显存、8×16 ASCII + 16×16 汉字、整屏 flush |
| `mcu/.../oled_font.h`（自动生成） | `tool/gen_oled_font.py` 从系统字体渲染、二值化导出的字模（96 个 ASCII + 24 个汉字） |
| `mcu/.../main.c` | USART2+DMA+IDLE 收包、`oled_refresh()` 版式、主循环里"内容变了才刷 + 每 3 秒补刷"、UART 状态行加 `cfg=ok/bad oled=0/1` |
| `mcu/.../build.sh` | 编译列表加 `oled.c cfg_proto.c` |

## 5. 怎么验证

1. 烧固件：`tool\烧录STM32.bat`（约 8.4 KB Flash，占用 13%）
2. 看串口状态行的三个新字段（PA9 115200）：
   ```
   mode=PASS words/s=48780 fs=24390 ovr=0 cfg=3/0 oled=1
   ```
   - `cfg=3/0` → 收到 3 个合法包、0 个坏包；一直是 `0/0` 说明**旁听线没接**（或声卡桥没在跑）
   - `oled=1` → 屏有应答；`0` 说明 I2C 没通（接线/地址 0x3C/上拉）
3. 不听串口也行：`tool/check_mcu_state.py` 那种读 RAM 的办法读
   `g_cfg_ok@0x20000040`、`g_cfg_bad@0x2000002C`。
4. 上位机里换模块/拖滑条，屏幕应在 0.3 秒内跟着变。

## 6. 已知限制

- 汉字只收了 24 个（变/调/分/离/直/通/环/形/回/声/中/置/本/地/模/型/人/伴/奏/半/音/增/益/…），
  想加字改 `tool/gen_oled_font.py` 里的 `CJK` 字符串再重跑一次即可（每个字 32 字节 Flash）。
- 屏幕只在内容变化或每 3 秒刷一次；改滑条时最坏有 0.3 秒延迟（轮询节流）。
- 一帧 1024 字节 @400 kHz 约 25 ms，这段时间主循环被占住，但音频全在中断里跑，听不出影响。
