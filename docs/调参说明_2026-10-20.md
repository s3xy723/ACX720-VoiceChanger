## 1. 界面：两路双声道频谱 → 四路波形

右上图原来的结构是「上下两条频谱带，每格再劈成左右两半」。半格在  
1240 px 窗口里只有 3~4 px，分离模式改成「左人声 / 右伴奏」之后，  
输出两路的能量差很大，半格根本读不出来。

现在默认是 **四条独立泳道**：

| 泳道 | 内容   | 颜色  |
| -- | ---- | --- |
| 1  | 输入 L | 亮蓝  |
| 2  | 输入 R | 淡蓝  |
| 3  | 输出 L | 琥珀  |
| 4  | 输出 R | 淡琥珀 |

- 每条左侧直接显示该路峰值 dBFS，无信号时写「无信号」。
- **四路共用同一个量程**（右下角 `±0.xxx FS`），这样两路之间的  
  相对电平是真的，不会每路各自拉满。
- 实时模式画最近约 4 k 点的滚动波形；文件模式画整段包络。
- 右上「视图」可切回原来的频谱对照，功能没有丢。
- 「显示」下拉仍支持 `同屏四路 / 只看左 / 只看右 / 平均`。

实现：`host/spectrum.py` 新增 `QuadScope`；`host/host_app.py` 的  
`_build_spectrum` / `_poll` / `_show_file_spectrum` 同时喂波形和频谱两份数据。

## 3. 调参：纯 DSP 分离的默认值

调参脚本：`tool/tune_split_va.py`（合成混音 + SI-SDR 网格）。

合成混音刻意做成最难的情况：人声居中、**贝斯和底鼓也居中**，  
吉他硬左/硬右，人声与伴奏 RMS 接近。中置提取天然会把居中的  
贝斯/底鼓一起算进人声。

### 关键发现：伴奏低频保护

如果拿完整人声估计直接去减伴奏，贝斯/底鼓会被一起扣掉。实测：

| 方案                 | 人声 SI-SDR | 伴奏 SI-SDR          |
| ------------------ | --------- | ------------------ |
| 不分离（基线）            | −1.69 dB  | +1.64 dB           |
| 中置分离，全频段扣人声        | −0.64 dB  | **−2.46 dB**（伴奏变薄） |
| 中置分离 + 120 Hz 低频保护 | −0.64 dB  | **+9.38 dB**       |

做法：人声输出仍用完整掩蔽（低频男声不能丢），但**从伴奏里扣除的  
那一份**先过 120 Hz 一阶高通。代价是 120 Hz 以下的人声会在伴奏里留  
一点（实测泄漏 −14 dB），换回完整的低音。

### 最终默认值

| 参数             | 默认          | 说明                            |
| -------------- | ----------- | ----------------------------- |
| 分离深度           | 100%        | 人声全取出                         |
| 非谐波保留          | 20%         | 气声/齿音与分离度的平衡点                 |
| 谐波梳状掩蔽         | 开           | 挡住不跟人声同谐波的乐器                  |
| 伴奏低频保护         | 120 Hz      | 实测最优；80 Hz 保护不足，160 Hz 人声泄漏变多 |
| 中置掩蔽下限 `floor` | 0.06        | 比 0 多约 0.3 dB，听感更自然           |
| 门限 `gate_db`   | −40 dB      | 再低会收进泄漏，再高会削掉弱音               |
| 人声/伴奏音量        | 100% / 100% | 两路独立                          |

整段处理速度约 3.8 秒 / 20 秒音频（约 5.3 倍实时），实时模式延迟  
1024 点 ≈ 21 ms。

## 4. COM3 板子链路检查

本机 `COM3` 存在，但**没有收到任何数据**：

- 波特率 9600 / 19200 / 38400 / 57600 / 115200 / 230400 / 460800 / 921600  
  全部为空。
- 115200 下切换 DTR/RTS（有些 USB-TTL 用 DTR 复位 STM32）仍为空。
- 串口能正常打开、不报错，说明不是被占用，而是**对端没有发数据**。

按工程里的固件（`mcu/f103_spi_mcp4922/main.c`），STM32 应该在  
USART1（PA9，115200-8-N-1）每 500 ms 打印一行：

```
mode=PASS words/s=... fs=24414 ovr=0
```

没有这行，优先排查：

1. **固件是否真的烧进 STM32**（ST-Link / STM32CubeProgrammer）。
2. **PA9(TX) 是否接到 USB-TTL 的 RX**，GND 是否共地。
3. COM3 是否其实是板载 FPGA 的 USB-UART（本设计没有 UART 输出，  
   只有 SPI 镜像），而不是 STM32 的 USART1。
4. 若串口是 USB-TTL，注意 3.3V 电平，不要把 5V TX 直接接 PA9。

## 5. 怎么运行

源码模式（推荐，改完立刻生效）：

```
host\运行上位机.bat
```

脚本会自动找同时有 `numpy + tkinter + sounddevice` 的 Python；  
依赖清单见 `host/requirements.txt`。

EXE 模式：现在提供的是**文件夹版**（不再用单文件 onefile）：

```
dist\ACX720VoiceChanger\ACX720VoiceChanger.exe
```

桌面快捷方式：`C:\Users\Administrator\Desktop\ACX720变声器.lnk`。

为什么改文件夹版：单文件 EXE 每次启动都要把 60 MB 解压到  
`%TEMP%\_MEIxxxx`，在这台机器上会弹  
**"Could not create temporary directory!"**（临时目录/杀软策略拦截）。  
文件夹版不写临时目录，双击即开。

- 整个文件夹约 143 MB，exe 本体 6.8 MB
- 内含 sounddevice 0.5.6 / soundfile 0.14.0 / PyAV 19.0.1 / numpy 2.3.5
- 本次新增的四路波形、内嵌播放器、人声/伴奏分离都在里面
- 已用文件夹版自己的 `--selftest` 跑过：**RESULT: ALL PASS**

重新打包：`host\build_exe.bat`（现在默认生成文件夹版）。
