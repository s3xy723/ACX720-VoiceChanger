# 单片机控制发声 —— 链路跑通记录（2026-10-22）

> 结论先行：**链路已跑通**。PC → COM5(1.5 Mbaud) → FPGA → SPI → STM32 → MCP4922 → PAM8403 → 喇叭
> 全程打通，1 kHz 门控音实测 **ON−OFF +43.5 dB（直发）/ +24.2 dB（VB-Cable 真实应用路径）**，均 PASS。
>
> 本轮真正的阻塞点只有一个：**FPGA 里跑的不是本工程的比特流**（SRAM 掉电丢失，且上次烧的是带
> 3 个 ILA 核的另一份设计）。重烧 `voice_changer.bit` 后立刻恢复。

## 0. 上位机（exe）里选哪个设备才能从音响出声

**选输出设备：**
```
CABLE Input (VB-Audio Virtual Cable)   [Windows WASAPI]
```

两个地方都有这个下拉框，任选其一设置即可：

| 位置 | 标签 | 默认值 |
|---|---|---|
| **实时变声** 页 | 「输出设备（扬声器/耳机）」 | 系统默认扬声器 |
| **内嵌播放器** 底栏 | 「输出」（第一项是「（系统默认）」） | 系统默认 |

下拉框里会出现三条 CABLE，实测三条都能开流，**推荐 WASAPI 那条**（ch=2，与桥接程序抓的
WASAPI `CABLE Output` 同源；另两条是 MME / DirectSound，显示 8 声道）：

```
dev=6    CABLE Input (VB-Audio Virtual C   [MME]                     ch=8  OK
dev=13   CABLE Input (VB-Audio Virtual Cable)   [Windows DirectSound] ch=8  OK
dev=16   CABLE Input (VB-Audio Virtual Cable)   [Windows WASAPI]      ch=2  OK   ← 选这个
```

> ⚠ 不要选 `Speakers (VB-Audio Point)` —— 那是另一条虚拟线（VB-Audio Point），
> 桥接程序抓的是 **VB-Audio Virtual Cable**，两者不互通。

**并且必须同时运行桥接程序**（`tool\启动FPGA声卡桥.bat`），否则选了也没用：

```
上位机 → CABLE Input ─┐
                      ├─ 虚拟线 ─→ CABLE Output ─→ 桥接程序 ─→ COM5(1.5Mbaud)
                                                                    ↓
                                          FPGA → SPI → STM32 → MCP4922 → 喇叭
```

关掉桥接窗口 = 断开到 FPGA 的音频。

实测（输出设备 = dev16 WASAPI，1 kHz 门控音）：ON −41.1 dB / OFF −90.2 dB，**ON−OFF +49.2 dB**。

### 0.1 界面上的「声卡桥」状态条与一键启动

实时变声页、输出设备下拉框正下方多了一条：

```
声卡桥   未运行 / 运行中（PID xxxx）/ 运行中（外部启动）      [一键启动 | 停止]
```

- 状态每 2 秒刷一次（`BRIDGE_POLL_SEC`）。自己拉起来的看进程句柄；
  别人（比如你双击 bat）拉起来的，靠**串口被独占**来判断 —— pyserial 打开
  CH340 是独占的，打不开就说明有桥在用它，此时按钮变成「外部运行中」并置灰。
- 「一键启动」会自己找一个装齐 `pyserial/numpy/sounddevice` 的解释器
  （`ACX720_PYTHON` 环境变量 → 本机 dsh 运行时 → AppData 的 Python → PATH）；
  实在找不到就退回双击 `启动FPGA声卡桥.bat`。
- 找不到 CH340 时显示「未运行（没找到 CH340）」，按钮仍可点，起桥后自己会报串口错。

> 顺带一个发现：发 800 Hz 纯音时，喇叭里最强的是 **1050 / 1100 / 1300 Hz**，不是 800 Hz。
> 说明板上的拨码开关 `sw[7:6]` **没有停在 00（直通）**，多半停在「变调」档
> （1100/800 = 1.375，正好等于代码里 `v=9` 的变调比）。
> **想听原声就把 sw[7:6] 拨到 00**，想听变调就用 sw[5:2] 调档位。

## 1. 控制路径（从单片机到发声模块）

```
                      SPI1 从机 16bit 模式0,0
   FPGA (A13/A14/A15) ─────────────────────────► STM32F103C8T6
     mcu_sclk → PA5 (SPI1_SCK)                     │
     mcu_csn  → PA4 (SPI1_NSS + EXTI4 帧同步)      │ SPI2 主机 16bit 模式0,0 @4.5MHz
     mcu_mosi → PA7 (SPI1_MOSI)                    ▼
                                              MCP4922 (12bit 双路 DAC)
                                              PB13=SCK  PB15=SDI  PB12=CS̄  PB0=LDAC̄
                                                    │
                                              两级 RC + 10µF 隔直
                                                    ▼
                                              PAM8403 → 2× 4Ω 3W 喇叭
```

- **FPGA→STM32 是 SPI，不是串口**。CH340/COM 口只承担两件事：
  ① PC→FPGA 的音频输入（1.5 Mbaud，ACX720 板载 CH340）；
  ② STM32 PA9 的调试日志（可选，不参与音频）。
- **CS̄ 每帧一个下降沿**（不是每字），下降沿 = 帧起点 = 左声道字。STM32 用 EXTI4 抓它做硬同步，
  所以偶尔丢一个字只会脏一帧，**不会累积成左右声道永久互换**（这是老版本的经典症状）。
- 左右两字写完后拉一次 LDAC̄（PB0，≥100 ns），两路 DAC 同一时刻更新 → 左右零相差。

## 2. 触发条件（缺一不可）

| # | 条件 | 说明 |
|---|---|---|
| 1 | **FPGA 已加载本工程比特流** | ★ 本轮阻塞点。`program.tcl` 用的是 `program_hw_devices`，**只写 SRAM**，掉电即丢。每次上电都要重烧一次。 |
| 2 | FPGA 的 GPIO0 bank = **3.3 V** | 跳在 1.8/2.5 V 时 STM32 边沿不可靠 |
| 3 | **共地** | P7 的 GND 用 **pin 12 或 pin 30**；pin 11=5V、pin 29=3.3V 不能当 GND |
| 4 | STM32 跑 **Design A** 固件 | `mcu/f103_spi_mcp4922`（外置 MCP4922）。**不要烧** `spi2_dma_dac.c`（Design B，内部 DAC PA4/PA5，与当前接线冲突） |
| 5 | 音频源 | PC→FPGA UART 帧**优先**；100 ms 没有帧则自动回退到 ES8388 的 ADC 输入 |

> STM32 的 440 Hz 自检音**只在"超过 1 s 没收到 FPGA 字"时才出现**。所以：
> 接上并配置好 FPGA 之后听不到自检音是**正常的**；反过来，**一直有自检音 = FPGA 没送数据**。

## 3. 本轮实测：怎么确认"发声控制已生效"

### 3.1 数字段（用 ST-Link 读活体状态，不依赖串口）

`tool\thirdparty\openocd\bin\openocd.exe -s <scripts> -f interface/stlink.cfg -f target/stm32f1x.cfg`

当前板上实测（RAM 全局地址，本次烧录的这版与本地 elf 的布局不同，以实测为准）：

| 变量 | 地址 | 实测 | 含义 |
|---|---|---|---|
| `g_ms` | `0x2000000C` | 持续 +1130/s | SysTick 在跑 → 固件活着 |
| `g_last_word_ms` | `0x20000010` | **== g_ms** | 刚收到 FPGA 字 → 处于 PASS 直通 |
| `g_words` | `0x20000014` | **+48,706 字/秒**（理论 2×24414=48,828） | ★ SPI1 正在收音频流 |
| `g_ovr` | `0x20000018` | **0** | 没有溢出，链路跟得上 |
| `g_left/g_right` | `0x2000001C/1E` | 随音频变化 | 样本在更新 |
| `g_test_mode` | `0x20000021` | **0** | 已退出自检音，走直通 |

关键外设寄存器（全部正确）：

```
SPI1_CR1   0x0840   从机 + 16bit + 硬件 NSS
SPI2_CR1   0x0B54   主机 + 16bit + SSM/SSI + BR/8 + SPE   → SCK = 36MHz/8 = 4.5 MHz
GPIOB_CRH  0xB4B34444   PB13=0xB(SCK 复用推挽) PB12=0x3(CS̄ 推挽) PB15=0xB   ★ 修复已生效
GPIOA_CRL  0x44444444   PA4/PA5/PA7 浮空输入（SPI1 从机三根线）
GPIOA_CRH  0x444444B4   PA9 = USART1_TX
DAC_CR     0x00000000   内部 DAC 未用 → 确认是 Design A 而非 Design B
```

SPI2_SR 连续采样 40 次，其中 3 次 `BSY=1` —— **SPI2 确实在往 MCP4922 移位输出**。
（常态 `SR=0x43` 里的 `OVR=1` 是正常的：SPI2 是只写主机，MISO 上的字节没人读，必然溢出标志。）

### 3.2 模拟段（门控 ON/OFF + 麦克风）

```
python tool/verify_hw_audio_uart.py  --port COM5 --freq 1000    # 直发
python tool/verify_hw_audio_cable.py 1000                        # VB-Cable 真实应用路径
```

```
频点     ON 窗    OFF 窗   ON−OFF
1000   -36.2 dB  -79.8 dB  +43.5 dB   ← 所发频点
1500   -40.2 dB  -72.8 dB  +32.6 dB   ← 对照（没发）
250    -76.0 dB  -89.3 dB  +13.3 dB   ← 对照（没发）
RESULT: PASS 喇叭出声，且只在我们发的那个频点上（链路闭环）
```

### 3.3 一句话判据

**能听到"我们发的那个频率"的声音，且只在这个频点上** —— 而不是"声音变大了"。
房间噪声会让单纯的音量对比出现假阳性（历史上同一套代码跑出过 +17.9 dB 和 +2.3 dB 两个相反结论）。

## 4. 本轮修掉的问题

| 问题 | 现象 | 处置 |
|---|---|---|
| ★ **FPGA 里不是本工程的比特流** | 板上跑的是带 3 个 ILA 核的另一份设计 → 不发 SPI，`g_words` 20 分钟只涨到 1 | 用 Vivado 2023.2 + JTAG-HS2 重烧 `vivado_prj/voice_changer.bit`，回显立刻 1144/1144 |
| ★ **CH340 串口号漂移** | 脚本写死 COM4，实际是 **COM5** → "帧全发了、板子没反应" | `verify_hw_audio_uart.py` / `verify_hw_audio_cable.py` 增加 `--port` 与单 CH340 自动识别 |
| ★ **cable 测试把 ON/OFF 判反** | 明明出声，脚本报 −19.4 dB | 分析窗多加了 2.5 s（`PRE_ROLL` 重复计 + 桥接初始化被算进录音时间轴），周期 1.4 s 下 2.5 mod 1.4 = 1.1 s 正好落进另一半。已改为 `+ PRE_ROLL` |
| PA9 调试串口读不到 | COM5 各波特率一律 0 字节 | PA9 当前**没有**接 USB-UART（COM5 是 FPGA 板载 CH340）。音频不受影响 |

## 5. 一个遗留的固件时钟偏差（不影响出声，影响日志）

实测 `DWT_CYCCNT`：**SYSCLK = 72.4 MHz**，而源码 `clock_init_64mhz()` 想要的是 64 MHz。
反汇编板上固件（`0x08000288`/`0x08000292`）确认它写的是：

```
bic.w r0, r0, #0x3F0000        ; 清 PLLMUL/PLLSRC 位域
orr.w r0, r0, #0x1D0000        ; PLLSRC=1(HSE)  PLLMUL=0111b(×9)  → 8MHz × 9 = 72 MHz
```

而 `RCC_CFGR` 实测 `0x001D040A` 与之吻合。即：**烧进去的这版用的是 HSE×9，不是源码里的 HSI/2×16**。

后果只有一个是实质性的：

- `USART1_BRR = 0x22B` 是按 64 MHz 算的；在 72 MHz 下实际波特率 = **129,870**（不是 115200）。
  → 接了 PA9 也要用 **129870** 去读，或者改 `BRR = 0x271`，否则串口是一堆乱码。
- 自检音实际是 **494.6 Hz**（TIM2 ARR=2620 在 72 MHz 下是 27.47 kHz），不是 440 Hz。
- **音频通路不受影响**：SPI1 由 FPGA 提供时钟，STM32 只是在 ISR 里转发，与 SYSCLK 无关。
- SPI2 仍在工作范围内：PCLK1 = 36 MHz，BR=/8 → **4.5 MHz**（MCP4922 上限 20 MHz）。

## 7. 排查顺序（按此顺序，不要跳）

1. **回显 100% 吗？** 不是 → FPGA 没配置好（第 1 步重烧）。
2. **`g_words` 在涨吗？** 不涨 → 查 A13/A14/A15 三根线 + 共地 + GPIO0 是 3.3 V。
3. **`g_ovr > 0` 吗？** 大于 0 → MCU 处理跟不上（检查是否有人关了中断太久）。
4. 以上都正常但没声 → 才轮到模拟段：
   - 万用表直流档量 MCP4922 的 VOUTA/VOUTB：静音时应 ≈ 1.65 V；恒 0 V 查 SHDN/VREF/SPI2。
   - 手指碰 PAM8403 的 L IN / R IN：有"嗡"声 → 功放和喇叭好，问题在 DAC/RC。
   - 1.5 V 电池碰喇叭两端：有"咔啦"声 → 喇叭好。
