### 固件：发现并修了三个真 Bug

原 `firmware.hex` 烧进去后 ST-Link 显示 **HardFault**，PC 跳到
`0xf8d5c800` 这类非法地址，串口自然没有输出。

**Bug 1：64 MHz 没设 FLASH 等待周期**

`clock_init_64mhz()` 切到 64 MHz 前没有设 `FLASH_ACR.LATENCY = 2`，
取指读到错误指令，直接 HardFault。

**Bug 2：PRIMASK 恢复逻辑写反**

`dac_write()` / `dac_flush()` / 主循环里的临界区写的是：

```c
if (pm) { irq_enable(); }   // 错：pm=0（本来开中断）时反而把中断永久关掉
```

第一次 `dac_flush()` 后 `PRIMASK=1`，SysTick / EXTI4 / SPI1 全部停摆，
`g_ms` 卡在 1002、`g_words` 恒 0。已改成：

```c
if (!pm) { irq_enable(); }  // 只在进临界区前是开中断时才恢复
```

**Bug 3：EXTI4 的 NVIC 中断号写错**

`EXTI4` 是 **IRQ10**，代码写成了 `1u << 17`（那是 DMA1_Channel2）。
已改为 `NVIC_ISER0 = (1u << 10) | (1u << 28);`。

修完后实测：

```

g_ms    = 0x063E (1598，持续递增)
NVIC ISER0 = 0x10000400  (bit10 EXTI4 + bit28 TIM2)
USART1_CR1 = 0x00002008  (UE=1, TE=1)
GPIOA_IDR  = 0x0000DA13  (PA9 空闲高)
```

重新编译（arm-none-eabi-gcc 9.3.1）并烧录：

### FPGA→STM32 SPI：CS 有边沿，但收不到字

固件修好后读 STM32：

```
g_words        = 0        (SPI1 一个字都没收到)
SPI1_SR        = 0x82     (BSY|TXE，RXNE=0)
EXTI_PR        = 0x10     (PA4 确实出现过下降沿)
NVIC ISER0     = 0x10000400
```

PA4（CS̄）已经有边沿，说明 A14 这根线通了；但没有完整的 16 位字，
优先查另外两根和地：

1. FPGA **A13 (mclk/mcu_sclk)** → STM32 **PA5**。
2. FPGA **A15 (mcu_mosi)** → STM32 **PA7**。
3. FPGA GND → STM32 GND **必须共地**。
4. A13/A15 是否和 A14 接反/虚接。

SPI 通后 `g_words` 会持续增加，串口应显示
`mode=PASS words/s≈48828 fs=24414 ovr=0`。

### 串口：系统只认 COM4，COM3 是幽灵设备

`用户说 COM3`，但 Windows 当前的实测状态是：

```
USB-SERIAL CH340 (COM3)  Status: Unknown   <-- 不存在的幽灵记录
USB-SERIAL CH340 (COM4)  Status: OK        <-- 唯一活动端口
```

- `SerialPort.GetPortNames()` 只返回 **COM4**。
- 强制打开 `COM3` 报“端口 COM3 不存在”。
- COM4 115200 连续读 4 秒：**0 字符**。
- 9600 / 19200 / 38400 / 57600 / 115200 / 230400 / 460800 / 921600：
  **全部无数据**。

为排除固件问题，已用 ST-Link 直接往 `USART1_DR` 写 8 个 `0x55` 字节
（不经过主程序），COM4 仍然 0 字符。这说明：

**字节确实从 PA9 发出去了，但当前这颗活动 CH340（COM4）没有收到 →
PA9 与 CH340 RXD 之间没有电气连接，或者 COM4 根本不是接在 PA9 上的那颗 CH340。**

固件侧已经确认：UART 使能、PA9 空闲高、主循环在跑、64 MHz/115200 正确。

1. STM32 **PA9 (TX，LQFP48 第 30 脚)** 接 CH340 **RXD**（不是 TXD）。
2. STM32 PA10 (RX，第 31 脚) 接 CH340 TXD（可选，只收不发可以不接）。
3. 两块板 **GND 必须共地**；CH340 由 USB 供电时 VCC 不用接。
4. 设备管理器勾选“显示隐藏的设备”，COM3 是灰色的幽灵；实际活动的是 COM4。
5. 拔掉 CH340 的 USB，看哪个 COM 消失；再插回，确认新出现的端口号。
6. 可把 CH340 的 TXD 和 RXD 短接做回环：串口助手发什么就应收到什么，
   先证明 CH340 本身和驱动正常，再查 STM32 到 CH340 的两根线。

完整接线表（含 P7 的 A13/A14/A15、GND/5V/3.3V 引脚号）见
[`接线_STM32_CH340_FPGA.md`](接线_STM32_CH340_FPGA.md)。

> 现在可以随时用 `tool\烧录STM32.bat` 重新烧录固件；
> 用 `tool\烧录FPGA.bat` 烧 FPGA。两个脚本合起来就是当前统一调试配置。
