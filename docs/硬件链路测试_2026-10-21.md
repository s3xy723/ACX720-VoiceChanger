# 硬件音频链路测试记录（2026-10-21）

> 测试对象：上位机 → VB-Cable → 桥接 → COM4(CH340) → FPGA → SPI → STM32 → DAC → 功放 → 音响
> 测试脚本：`tool/verify_hw_audio_uart.py`（串口直发）、`tool/verify_hw_audio_cable.py`（应用真实路径）

## 0. 一句话结论

**数字段全部打通**（设备发现 / 连接 / 参数 / 下发 / 日志），FPGA 每帧都能正确解析
（烧新 bit 后回显 **1144/1144 = 100%**）；**但喇叭没有出声**。

失败点定位在 **STM32 固件陈旧**：板上跑的 `firmware.hex` 编于 **10-20 11:28**，
而音响驱动 `mcu/spi2_dma_dac.c` 的重写发生在 **10-21 01:50** —— 烧进板子的还是
那个没配系统时钟的旧驱动（TIM6 实际 2.7 kHz 而不是 24.4 kHz，慢 9 倍）。

## 2. 两个根因

### 根因 1（本次已解决）：FPGA 上的 bit 是旧的

时间线对不上：

| 文件/事件 | 时间 |
|---|---|
| `vivado_prj/voice_changer.bit`（含 UART 回显与 SPI 镜像） | 生成于 **10-20 23:23** |
| 最近一次成功烧录（日志 `PROGRAM DONE`） | **10-20 11:03** |

也就是说，最后一次烧录时 `voice_changer.bit` 里装的还是**更早**的设计。
于是：串口数据进得去，FPGA 里根本没有 `uart_audio_rx`，自然一个字节都回不来。

**处置**：用 Vivado 2023.2 + Digilent JTAG-HS2 重烧当前 bit ——

```
Target device: xc7a35t_0
INFO: [Labtools 27-3164] End of startup status: HIGH
================ PROGRAM DONE ================
```

重烧后回显立刻从 0 变成 100%。**这一步是可复现的因果，不是巧合。**

### 根因 2（未解决，下一步要做）：STM32 固件还是旧的

| 文件 | 时间 |
|---|---|
| `mcu/f103_spi_mcp4922/firmware.hex`（在板子里跑的） | **10-20 11:28** |
| `mcu/spi2_dma_dac.c`（音响驱动重写：时钟初始化 + ARR 2948 + 写指针修正 + 整帧对齐丢补） | **10-21 01:50** |

旧驱动的关键缺陷：**从没配置过系统时钟**，复位后默认 HSI 8 MHz，而 TIM6 的 ARR
是按 72 MHz 算的，实际输出帧率只有 **2.7 kHz** 而不是 24.4 kHz（慢 9 倍）。
这正是"能出声但完全听不清"、以及这次"完全测不到声"的最可能原因。

## 3. 出声判据为什么这么设计（踩过的坑）

第一次用"发声期间 vs 之前静默"的对比，同一套代码跑两次结论相反：

| 次数 | 环境 | 440 Hz 提升 | 宽带 RMS |
|---|---|---|---|
| 第 1 次 | 屋里安静 | **+17.9 dB** | ×47 |
| 第 2 次 | 屋里有人声 | +2.3 dB | ×0.63 |

那个 +17.9 dB 是**假阳性**：环境噪声变了，单点对比根本站不住。
所以改成两条硬要求：

1. **门控 ON/OFF**：0.7 s 发 + 0.7 s 停，重复 4 轮，ON 窗与 OFF 窗取自
   **同一段连续录音的相邻时间**，环境噪声对两者相同，差值只剩链路自己的贡献；
2. **对照频点**：同时测"没发"的频点（1.5×freq、250 Hz、freq/9…）。
   只有主频点明显高出对照频点，才算真的听到了声音。

按这个判据，本次 1 kHz 的 ON−OFF 是 +3.0 dB，而对照频点最高 +8.4 dB ——
**没有任何频点突出**，判定为无声。

## 5. 本次环境限制（不是链路问题）

- **OpenOCD 在本会话里读不到配置文件**：给它明确存在的绝对路径
  （`…\openocd\scripts\interface\stlink.cfg`，904 字节实体文件，PowerShell 也确认存在），
  它仍报 `Can't find …`。同一个文件层问题此前也让沙箱内构建的 EXE 无法原地运行。
  所以**"用 ST-Link 读 TIM6/DMA 寄存器"这条硬判据没能跑成**。
  请在普通终端自行执行：
  ```
  tool\thirdparty\openocd\bin\openocd.exe ^
    -f tool\thirdparty\openocd\openocd\scripts\interface\stlink.cfg ^
    -f tool\thirdparty\openocd\openocd\scripts\target\stm32f1x.cfg ^
    -c "init" -c "mww 0xE000EDFC 0x01000000" -c "mww 0xE0001004 0" ^
    -c "sleep 100" -c "mdw 0xE0001004" -c "mdw 0x40021004" ^
    -c "mdw 0x40001024" -c "sleep 20" -c "mdw 0x40001024" ^
    -c "mdw 0x40020048" -c "shutdown"
  ```
  预期：`DWT_CYCCNT/0.1 s ≈ 7.2e6`（即 72 MHz，验证时钟修复落地）；
  `TIM6_CNT` 两次读数差 ≈ 24414×Δt；`DMA1_Channel4->CNDTR` 在变化（DMA 在搬数）。
- 麦克风是笔记本阵列，远场拾音弱；要更可靠的判据得把麦克风贴近喇叭，
  或直接从 DAC 输出取电信号。
