## 1. 上一轮错在哪

上一轮给「分离」加了两个东西：

1. **鼓侧链 Wiener 掩蔽**（`host/drum_suppress.py`）：用 demucs 输出的 drums 源
   当参考，把人声轨里"鼓比人声强"的时频点压下去。
2. **默认档换成 htdemucs_ft**（四模型集成）。

用户反馈：**"依然不符合要求，甚至更差了"**，具体是"人声变闷/变薄/忽大忽小"。

根因是**当时那个指标看不见损伤**。上一轮报的成果是：

> 端到端鼓残留 −22.0 → −28.0 dB，人声仅降 0.14 dB

这个"人声仅降 0.14 dB"是在**全频段 RMS** 上算的。而这套掩蔽真正的代价发生在
别处，全频段 RMS 恰好把它平均掉了。用这一版的判据重算：

| 版本 | 低频含量（30–110 Hz 相对人声中频） | 高频含量（7–14 kHz 相对中频） |
|---|---|---|
| 上一版（带鼓侧链） | **−30.0 dB** | −19.7 dB |
| 这一版（纯 demucs） | **−26.7 dB** | −19.7 dB |

**低频被砍掉 3.3 dB，高频纹丝不动。** 也就是说它只做了一件事：把人声的厚度削了。
男声的厚度在 100–250 Hz，正好是基频所在，削 3.3 dB 听上去就是"变薄、变闷"；
而掩蔽随鼓点开合，逐帧增益在跳，听上去就是"忽大忽小"。

教训：**任何"按需 hangở在—人声轨上的后处理"，必须同时报"降了什么"和"伤了什么"，
两条都是负数时才算改善。** 只看其中一条必出错。

## 2. 这一轮的度量方法（每条都带对照）

`tool/sep_eval.py` 给每个候选同时算三类数：

### A. 残留：复数投影解释率
逐帧把人声轨 V 投影到伴奏轨 A 上：

```
c = <A, V> / <A, A>      残差 = V − c·A       解释率 = 1 − ||残差||²/||V||²
```

用**复数**投影是关键：漏进人声轨的伴奏和伴奏轨本身是同源同相的，只用幅度做比
会把它们算成"没关系"。分 MID / HI / HH 三段报，取"有能量的帧里最差的一成"（p90）
——用户抱怨的本来就是"某一瞬间听得见"，不是平均值。

### B. 损伤：只看人声占优点
在 `|V| > 2|A|` 且落在 150–5000 Hz 的时频点上统计处理前后能量差。这些点按定义
几乎不含伴奏，在那里掉能量就是实打实的人声损伤。

### C. 抖动：逐帧增益的标准差
`g(t) = |V'|/|V|`，取有人声的帧上的标准差。时变掩蔽的 artifact 直接量出来。

### 三个对照（不做这些，数字就是装饰）

| 对照 | 做法 | 结论 |
|---|---|---|
| **指标自身有效吗** | 粗暴低通到 8 kHz | HH_p90 从 −3.5 dB 掉到 −16.4 dB → 指标真能量 HF |
| **它量的是频谱相似还是对齐泄漏** | 把伴奏整体循环移位 13 s | HI 由 −4.9 变 −15.6 dB → 量的是**对齐**泄漏，不是频谱长得像 |
| **LF / LM 两段的解释率可信吗** | 同上 | LF −5.41 → −5.43，**几乎没变** → 低频每帧只有几个频点，一个复数标量就能拟合几乎任何东西，**这两列不可信，已弃用** |
| **损伤/抖动指标报得出来吗** | 故意加 −2 dB 衰减 | voc_loss 报 −2.00 dB，符合预期 |

## 3. 关键发现：分离本体是好的

拿**开头 0.6–22 秒的纯器乐段**（确定无人声）当标尺——这段里人声轨响多少就是漏多少，
不需要任何假设：

| 配置 | 22 s 片段耗时 | 纯器乐段漏音（相对混音） | 倍实时 |
|---|---|---|---|
| htdemucs, shifts 2, overlap 0.50 | 2.1 s | −61.3 dB | 0.10× |
| htdemucs, shifts 2, overlap 0.75 | 4.1 s | −62.0 dB | 0.19× |
| htdemucs, shifts 2, overlap 0.90 | 8.3 s | −62.7 dB | 0.38× |
| **htdemucs_ft, shifts 2, overlap 0.50** | **7.1 s** | **−66.6 dB** | **0.32×** |

（htdemucs_ft 是 demucs 官方微调集成，4 个模型平均。）

结论：

- **漏音在 −60 dB 量级**，这个量级不可能被听见。进一步优化算法是没意义的。
- **htdemucs_ft 既最干净又比实时快 3 倍**，默认档保持"高质"是对的。
- htdemucs 加到 0.90 重叠是**又慢又不如 ft**（0.38× / −62.7 dB），别那么调。

另外三条被数据否掉的猜想，一并记下来避免重复踩：

- **"人声轨里有一层镲"**：人声轨的 8–16 kHz 电平几乎恒定（中频从 +2 dB 摆到
  +26 dB 时它只在 −1~−7 dB 间微动），且三个模型完全一致（±0.1 dB）。
  这是素材本身的性质，不是某个模型的锅，也不是能靠换模型修的东西。
- **"漏了贝斯"**：人声轨的低频比混音低 37.7 dB，而且它跟 80–250 Hz 的包络既不跟
  人声中频同步（r=+0.06）也不跟鼓同步（r=−0.05）。低频是伪问题。
  任何针对低频的处理首先砍的是人声自己的厚度。
- **"导出成立体声把音质搞坏了"**：人声轨 L/R 相关 0.937，且 Side 声道的高频
  比 Mid 还低 8.5 dB。立体声导出无害。

## 4. 真正的病根：拿双轨文件判断分离质量

分离模块的主输出是**左声道=人声、右声道=伴奏**。这个文件：

- 用耳机听 → 左耳人声右耳伴奏；
- 用音箱听 → 两条声道在空气里**直接混回原曲**。

两种情况下都不可能听出"分离干不干净"。而用户正是在上位机的内嵌播放器里听这个
文件判断的（他选的答案是"界面里直接点试听"）。于是每一轮"优化"都得不到正确反馈。

**修复**：文件页新增「试听哪一路」下拉，处理完成后默认装 **只听人声**（左右两耳
同播，音箱上也能完整听到）。可选 只听伴奏 / 原样双轨。非分离模块该控件自动禁用。

回归测试 `test_host.py::test_audition_route`：把 `_audition_data_now` 改成"一律返回
主输出"，5 条断言里 3 条 FAIL（负对照仍 PASS），确认这条测试不是恒真的装饰。

## 6. 给下一轮的规矩

1. 先确认**用什么在听**。判断分离质量必须只听一路，主输出不能作为依据。
2. 任何加在人声轨上的后处理，必须同时报"残留降了几个 dB"和"人声自己的厚度掉了
   几个 dB"。**只有前者不符合 результа就撤。**
3. 新指标上线前先跑负对照（时间移位 / 故意损伤），跑不出来就不许用它下结论。
4. 纯器乐段的漏音是最好的第一判据——它不需要任何假设，也不依赖运气好的副歌片段。
