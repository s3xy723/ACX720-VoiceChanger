### 0.2 真仿真 + 真综合抓出来的 bug（都是"看代码看不出来"的）

1. **乘法位宽**：Verilog 里 `a*b` 的位宽只由**操作数**决定，跟赋值目标多宽
   无关（跟 VHDL 不一样）。`mid_v(24) × win(17)` 被截回 24 位，加窗后谱只剩
   ±100（应该是 ±1e5）。修法：每个乘法先落到显式加宽的线上再移位。
2. **FFT 读延迟（第一次）**：`rd_re` 是寄存器输出，给地址后要两拍才有效，
   读状态只等了一拍 → 整条谱循环移一个 bin（低频就是 23.8 Hz 偏差），基频全错。
3. **帧跳写成 512**：`wp[8:0]==0` 是 %512，不是 %256，每点只被两帧覆盖，
   Hann² 之和从 1.5 掉到 1，OLA 的 2/3 就补错了。
4. **改了 FFT 却只重跑了一半验证**（这次最贵的一个）：
   为了让 BRAM 能推断，给 `fft1024` 加了端口复用，`rd_re` 从 `ra_re[rbr]`
   （单级）变成 `ra_d0_re`（两级）——**读延迟多了一拍**。当时只重跑了 FFT 裸
   仿真（3/3 PASS），没重跑 `separation_core`，于是第 2 条那个 bug 原样复现：
   mid 谱和模型差到 222489，但峰值一模一样（整体移位就是这副样子）。
   **教训：任何碰 `fft1024` 读通路的改动，`check_fft_sim.py` 和
   `check_sep_sim.py` 必须都重跑，只跑一个等于没验。**
5. **`warm` 被两个 always 块驱动**：仿真里"后写者赢"所以完全看不出来，
   综合才报 `Synth 8-6859 multi-driven`，而且复位清零会被吃掉。
6. **存储全被推成寄存器 / LUTRAM**：见 0.4 节。这条不是 bug 是架构问题，
   但后果一样致命——第一次综合直接 101% 超器件。

顺带修的：`fft1024` 输入取共轭原来用上一帧锁存的 `inv_r`（装载发生在
`start` 之前），改成用当前的 `inverse`。

### 0.3 一帧实测耗时

```
帧间隔   524,288 拍（256 点 × 2048 拍/点 = 10.49 ms）
一帧实测  117,389 拍            → 余量 4.47 倍
```

## 1. 为什么 FPGA 上可以做这个分离

关键数字：**音频速率下时间富余到离谱**。

```
采样率        fs = 24.414 kHz      （板载 ES8388，MCLK 12.5 MHz / 512）
帧跳          HOP = 256 点          → 一帧 10.49 ms
系统时钟      50 MHz               → 一帧 524,288 个时钟
一次 1024 点 FFT（单蝶形串行）       → 25,600 个时钟
一帧需要 5 次变换 + 逐点处理         → 约 138,000 个时钟
```

**余量 3.8 倍**。所以完全不需要并行蝶形、不需要多套 RAM——一个蝶形单元
按状态机轮流跑五次变换就够。这是"小芯片做大 FFT"的关键前提。

### 一帧的信号流

```
                    ┌──────────── 1024 点 ────────────┐
 din_l ─┬─► mid=(L+R)/2 ─► 加窗 ─► FFT ─► |mid|,∠mid
        │                                    │
 din_r ─┴─► side=(L-R)/2 ► 加窗 ─► FFT ─► |side|,∠side
                                             │
                    ┌────────────────────────┘
                    ▼
        逐频点 c=(|mid|-|side|)/|mid| ──► V = c·mid        （人声估计）
                    │
                    ├─► |V|² ─► IFFT ─► 自相关 acf[lag]
                    │                      │
                    │                      ▼
                    │         男 / 女两个迟滞区间各找一条基频
                    │                      │
                    │                      ▼
                    │              两位歌手判定（第 3.3 节）
                    │                      │
                    ▼                      ▼
        逐频点梳状竞争掩蔽 ──► Vm(男) / Vf(女)
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   IFFT(Vm) ─► 加窗 ─┐    IFFT(Vf) ─► 加窗 ─┐
                    ▼                       ▼
        acc_m += (男声帧)        acc_f += (女声帧)      （重叠相加）
                    │                       │
                    └───────────┬───────────┘
                                ▼
        dout_l = din_l - acc_f      dout_r = din_r - acc_m
        （男声留左、女声留右，伴奏两边原样不动）
```

固定延迟 **1024 点 = 42 ms**（要等最右那帧的右半窗）。

## 2. 已完成并验证的部分

### 2.1 `rtl/fft1024.v` —— 1024 点复数 FFT / IFFT

- **算法**：DIF（Gentleman-Sande），自然序入 / 位倒序出，单蝶形串行。
  旋转因子地址 = `j << s`，**一个移位，连乘法都不用**。
- **IFFT** 用共轭法 `IFFT(X) = conj(FFT(conj(X)))`，正反向共用一个引擎。
  于是"分析 → 掩蔽 → 合成"整圈增益恰好抵消，不用额外补偿。
- **定点**：24 位内部数据、Q15 旋转因子。
- **存储：单 RAM 原址**（这一版改的，详见 2.6）。
  一次变换 5120 个蝶形 × 3 拍 = **15,360 拍**，只占 2 块 BRAM36K。

### 2.2 缩放梯度的选择（踩坑记录）

最初**每一级都右移 1 位**（最保险，绝不溢出）。结果往返误差 **10%**——
"分析→掩蔽→合成"要过两次变换，20 次移位把 24 位有效位吃光了。

于是扫了一遍"从第几级开始缩放"（`tool/exp_fft_scale.py`）：

| 从第几级缩放 | 前向缩放 | 往返最大误差 | 相对误差 |
|---|---|---|---|
| 0 | 1/1024 | 29590 | **99.9%** ← 数值全被截断成 0 |
| 1 | 1/512 | 29503 | 99.6% |
| 2 | 1/256 | 29156 | 98.4% |
| 3 | 1/128 | 27768 | 93.8% |
| 4 | 1/64 | 22216 | 75.0% |
| **5** | **1/32** | **11.5** | **0.039%** ← 选这个 |

反直觉的是：**缩放越多越不准**——早期缩太狠，数值掉到整数以下直接被
截断成 0。第 5 级起步既留足了抗溢出余量，又保住了有效位。

顺带把舍入从"截断"改成"加半再移"：截断对负数向下取整，负半周会累积
直流偏置。

### 2.3 验证结果（`tool/sim_fft1024.py`，逐比特复刻 RTL）

```
[PASS] FFT→IFFT 往返误差小                最大绝对误差 11.5（相对 0.04%）
```

### 2.5 综合发现的一个坑：旋转因子表被推成了分布式 LUT

单独综合 FFT 引擎（`tool/synth_fft.tcl`）时，报告里出现：

```
|fft_twiddle | tw_re | 512x16 | LUT |
|fft_twiddle | tw_im | 512x16 | LUT |
```

只用 `case` 语句写 ROM，Vivado 会推成**分布式 LUT ROM**。
512×16×2 = 16 Kbit，要吃掉 **8000 多个 LUT —— 占 35T 的 40%**。
已经在生成脚本里给输出加 `(* rom_style = "block" *)` 修掉，
两块 18Kb BRAM 就能装下。

### 2.6 BRAM 推断的三条硬规矩（这一版最大的工作量都在这）

第一次综合 `separation_core` 的报告是这么写的：

```
WARNING: [Synth 8-4767] Trying to implement RAM 'ra_re_reg' in registers.
        1: RAM has multiple writes via different ports in same process.
RAM "ra_re_reg" dissolved into registers
ERROR:   [Synth 8-2914] Unsupported RAM template [separation_core.v:81]
Synthesis finished with 3 errors, ...   u_fft 占 384,932 / 407,424 cells
```

98 Kbit 的 RAM 全变成触发器 = **101,752 个 FF，35T 一共才 41,600 个**。
根因是 BRAM36K **只有 2 个端口**，而原来的写法是：

| 数组 | 端口数 | 结果 |
|---|---|---|
| `ra_re`（FFT 源） | 读 addr0 + 读 addr1 + 写 wr_addr + 回拷写 = **4** | 拆成寄存器 |
| `rb_re`（FFT 目的） | 读回拷 + 写 addr0 + 写 addr1 = **3** | 拆成寄存器 |
| `acc_m` / `acc_f` | 两处**异步**读 + 两个 always 块各写一 = 4 | `Synth 8-2914` 报错 |
| `buf_l/r`、`acf`、`sp_*`、`sd_mag` | 异步读 | 推成 LUTRAM，吃掉 4800 个 LUT |

修完之后（0.4 节的资源表）LUT 从 **101% 降到 56.6%**。做法总结成三条：

1. **一个 always 块只写一个口。**
   装载写和蝶形写如果走同一个口，必须写在**同一个**块里
   （`if (bf_we) ... else if (load_we) ...`，不能 `if` 两次）。
2. **读必须同步。** 7 系列 BRAM 没有异步读，`wire x = ram[addr]` 这种写法
   要么变 LUTRAM 要么直接报错。改成 `always @(posedge clk) x_r <= ram[addr];`
   之后，**每个用到的状态机都要多加一段等读**（`separation_core` 里
   S_MASK / S_LDPW / S_SOLO / S_PKM* / S_LD* 都因此改成了两段或三段）。
3. **RAM 不能出现在复位分支里**，清零靠 `initial`（综合时变成 BRAM 的
   INIT 值，不花逻辑）。带复位的 RAM 一定被拆成寄存器。

顺便：**DIF 蝶形天生就是原址的**（读 a、b，算完写回 a、b），所以
`fft1024` 只要一块 RAM，端口 A 管 a、端口 B 管 b，各 1 读 1 写，
正好是标准真双口模板 —— 既解决了端口数，还省掉了原来每级 1024 拍的
"目的→源"回拷（一次变换从 25,600 拍降到 15,360 拍）。

**这条改动付出了代价**：端口复用让 `rd_re` 从单级寄存器变成两级，
读延迟多一拍，直接引爆了 0.2 节第 4 条那个 bug。所以 2.6 和 0.2-4
必须一起看。

这条只有真综合过才会发现，看代码是看不出来的。

## 3. 分离主控的设计（RTL 未写完）

### 3.1 状态机

```
S_IDLE    收样本；256 点一帧结束 → 记下帧起点
S_EMIT    输出 256 点 = 缓冲样本 - 累加器；清该段累加器
S_LDMID   取 mid、加窗、写入 FFT 输入（1024 拍）
S_FMID    等 FFT 完成
S_RDMID   把 512 个 bin 读进 sp_re/sp_im
S_LDSIDE  取 side、加窗、写入 FFT
S_FSIDE   等完成
S_MASK    逐 bin：c=(|mid|-|side|)/|mid| → V=c·mid；算 |V|²
S_LDPW    把 |V|² 当实偶谱写入（re[k]=re[1024-k]=pw[k]）
S_FACF    等 IFFT 完成 → S_RDACF 存 1024 点自相关
S_PKMAX   扫两个迟滞区间，各取最大值（2×300 拍）
S_PKFIND  取"第一个过 85% 阈值"的迟滞 → lag_m / lag_f
S_CLRC    清梳状表
S_COMB    打梳状标记（谐波循环，见 3.4）
S_CMP     逐 bin 竞争 → Vm / Vf
S_LDVM/S_FIM/S_RDVM   逆变换出男声帧
S_LDVF/S_FIF/S_RDVF   逆变换出女声帧
S_OLA     加窗、补 2/3 增益、累加到 acc_m/acc_f
```

### 3.2 存储（实现后的实际清单，不是预算）

| 存储 | 尺寸 | 端口 | 落地 |
|---|---|---|---|
| `buf_l` / `buf_r` | 2048 × 16 ×2 | A 写+读 / B 读 | 2 × BRAM36 |
| `acc_m` / `acc_f` | 2048 × 24 ×2 | A 读改写 / B 读完即清 | 2 × (BRAM36+BRAM18) |
| `sp_re` / `sp_im` | 512 × 24 ×2 | 1 读 1 写 | 2 × BRAM18 |
| `sd_mag` | 512 × 24 | 1 读 1 写 | 1 × BRAM18 |
| `acf` | 1024 × 24 | 1 读 1 写 | 1 × BRAM36 |
| `cmb_m` / `cmb_f` | 512 × 2 ×2 | 读改写 + 相邻位 | 寄存器（2048 FF） |
| FFT 内部 `m_re` / `m_im` | 1024 × 24 ×2 | 真双口原址 | 2 × BRAM36 |
| twiddle / win / recip | 16 / 16 / 12 Kbit | ROM | BRAM（已加 rom_style） |
| **合计** | | | **10.5 / 50 块 BRAM** |

几个当时没预算到、实际省掉的东西：

- **`pw`（\|V\|²）和 `vm_*`/`vf_*`/`fr` 根本没单独开数组**。
  `pw` 现算现写进 FFT；男/女谱直接由 `sp_re/sp_im` 乘掩蔽系数得到并立刻
  装载，不落地；IFFT 结果读出来当拍就加窗累加，也不落地。
- **`acf` 的 1024 点只写不并行读**，所以是简单双口而不是真双口。
- `cmb_*` 留作寄存器：512×2 太小，做成 BRAM 省不了什么，
  反而"读-改-写 + 看左右邻居"的时序更麻烦。2048 个 FF 只占总量的 5%。

### 3.3 两位歌手的判定 —— 这是整个设计的核心

上位机靠"残差能量测试"解差八度歧义。硬件里做残差测试太贵，改用**迟滞关系**：

> 周期为 T 的信号，自相关在 T, 2T, 3T… 都出峰。
>
> - 女声唱 232 Hz → T=105 拍。男声区（139~348 拍）里会出现 **210 = 2T** 的峰。
>   → `lag_m ≈ 2·lag_f` ⇒ **只有女声**（男声区的峰只是 2T 鬼影）
> - 男声唱 118 Hz → T=207 拍。女声区（48~157 拍）里**不会**出峰
>   （含奇次谐波的信号在半周期处是负峰）。
>   → **只有男声**
> - 两个区间都出峰、且迟滞不构成整数倍 ⇒ **两人齐唱** ⇒ 走梳状竞争

这条规则正好覆盖了最常见的"男女差八度齐唱"，而且**只用比较和移位**，
不需要除法器。代价是严格八度齐唱（两人真的重合）时无法分开——那是
物理极限，不是实现问题。

### 3.4 梳状竞争掩蔽

单人时整段 V 都归他/她，不用梳子。两人齐唱时：

```
对每个谐波 h = 1..40：
    pos = (h * f0_bin_q8) >> 8          // 一个乘法 + 移位
    标记 cmb[pos] = 2，cmb[pos±1] = 1   // 平顶三角，跟上位机一致
掩蔽： m = cmb_x / (cmb_m + cmb_f)
```

分母只可能是 1..4，所以**用一个 4 项倒数小表就够了，不需要除法器**。

### 3.5 时钟预算核算

| 步骤 | 拍数（实现后） |
|---|---|
| 5 次变换（原址，无回拷；装载另算） | 5 × 15,360 = 76,800 |
| 4 次装载（mid / side / \|V\|² / 男 / 女，各 1024 点） | 5 × 2,049 ≈ 10,245 |
| 5 次结果读出（512/512/1024/1024/1024 点） | 4,096×2 + 3,072×3 ≈ 17,408 |
| 掩蔽逐 bin（18 步/bin） | 512 × 18 = 9,216 |
| 基频三趟扫描（2 拍/lag） | ≈ 1,060 |
| 梳状标记 + 清表 + solo 判据 | ≈ 1,600 |
| **仿真实测合计** | **117,389** |
| **预算** | **524,288** |
| **余量** | **4.47 倍** |

"读出"这一项比预算大，是因为所有谱/自相关/累加器都改成了同步读，
每个点要多等 1~2 拍。用 4 万多拍换 4800 个 LUT（LUT 从 101% 降到 56%），
在这颗器件上是一笔很划算的交易——这里最缺的是 LUT，不是时间。

即使把 NFFT 提到 2048（分辨率翻倍），也还放得下。

## 4. AI 能不能跑在 35T 上 —— 硬数字

### 4.1 器件与板子（从官方资料实测，不是估的）

- 器件 **XC7A35T**：20,800 LUT / 41,600 FF / **90 个 DSP48E1** /
  50 块 BRAM36K（共 1.8 Mbit）
- 板载 **DDR3：MT41K128M16JT-125**（美光 128M×16 = **2 Gbit = 256 MB**，
  16 位总线，DDR3-1600 ⇒ 峰值 **3.2 GB/s**）
- 现有工程占用：LUT 1231 / FF 833 / BRAM 9 / DSP 12

### 4.2 demucs（htdemucs）的需求

- **约 8000 万参数** ⇒ fp32 **334 MB**、int8 **84 MB**
- 算力：本机 CPU 实测 **3.6 倍实时**（`tool/proto_demucs.py`，
  人声 SI-SDR **+19 dB**），反推每秒音频约需 **8~25 GFLOP**
- 35T 在 100 MHz 下理论峰值 90 DSP × 2 × 100 M = 18 GOPS，
  实际能到 20~40% ⇒ **7~14 GOPS**

**结论：算力差 5~20 倍（做不到实时）。** 而且比算力更致命的是**带宽**——
transformer 的权重每份只参与很少次乘加（算术强度低），
要撑起 7 GOPS 就得每秒搬 0.8~16 GB 权重，而 DDR3 峰值只有 3.2 GB/s。

这不是"优化一下就行"，是**器件量级不匹配**。

### 4.3 用户选的路：小模型

用户明确选择"在 35T 上跑小型模型（不是 demucs）"。这条路**可行**，
但要说清楚它的定位：

- **可行**：一个 2~10 万参数的小型卷积/全连接网络（例如从
  `(|mid|, |side|)` 的 64 个 mel 频带特征预测 64 个频带的软掩蔽），
  权重 int8 只要 20~100 KB ⇒ **放得进片内 BRAM**，不用碰 DDR3；
  每帧约 2~10 万次乘加，95 帧/秒 ⇒ 2~10 MMAC/s ⇒ 一个 DSP 串行跑绰绰有余。
- **它的作用**是**替换中置掩蔽那一步**（`c=(|mid|-|side|)/|mid|`）——
  这一步恰恰是纯 DSP 最弱的地方（居中乐器会被一起当成"人声"搬走）。
- **代价**：我没有训练数据。需要先拿 demucs 在真实歌曲上生成
  伪标签（人声/伴奏），再训这个小模型来模仿它的掩蔽。用合成数据训
  出来的模型在真实音乐上大概率**还不如**第 3 节那套 DSP 规则。
  这条我在提问时已经说明，用户仍然选它。

**接口已经定好**（替换 `S_MASK` 里的 c 计算）：

```
输入  mag_mel[0..63]    |mid| 的 64 频带能量（对数域，int8）
      coh_mel[0..63]    (|mid|-|side|)/(|mid|+|side|)，即通道间一致性
网络  64 → 96 → 64 全连接，ReLU + 输出 sigmoid，int8 权重 / int32 累加
输出  mask[0..63]       每个频带的软掩蔽，上采样回 512 个 bin 后用
```
