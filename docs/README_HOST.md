# 上位机（PC 变声软件）

> **⚠ 2026-10-21 变更：分离只剩一种语义**
> 上位机与 FPGA 的输出**固定为「左声道 = 人声，右声道 = 伴奏」**。
> 旧的 `mf` 路由（男声→左、女声→右）已从 host 与 RTL 里**整条删除**。
> 下面若出现「男左女右」的描述，属于历史记录，不再是当前行为。

一个跑在本机 Python 上的变声器。**「变调 × FPGA 直算」这条路是 `rtl/` 里那套 Verilog 的
逐比特移植**：同样的 4096 点延迟线、同样的 512 点 Hann 窗 ROM、同样的 Q15 定点、
同样的饱和门限。所以在这条路上调好的参数，可以直接换算成板子上的拨码开关值——
界面左下角实时显示 `sw = xxxxxxxx`。其余三种组合板上没有，只在上位机侧有效。

**全链路都是双声道分别运算**：输入不论几路都规整成两路，左右各挂一条
**完全独立**的效果链（延迟线、相位、回声历史互不共用），峰值、削波、频谱
也按声道分开统计，任何地方都不做 L/R 混音。频谱把左右两个声道**同时**画出来。

**为长时间运行做了缓存管理**：日志、处理结果、素材都有上限/超时，
削波计数会随时间衰减，每 30 秒自动巡检一次。

## 操作逻辑：模块 × 引擎 × 输入

2026-10-14 重构。原来是把七种效果平铺成一列单选（直通 / 机器人 / 变调 / 回声 /
变调+回声 / 男女声分离 / 本地 AI 处理），一屏放不下，而且绝大多数参数对当前选项无效。
现在收敛成**三级单选**，面板长度固定，只显示当前组合用得到的参数：

```
模块（做什么）        引擎（谁算）                      输入（怎么喂）
├─ 变调              ├─ FPGA 直算（时域延迟线）         ├─ 实时变声（麦克风）
│                    └─ FPGA 内部小模型（频域提质）     └─ 文件变声（整段处理）
└─ 分离              ├─ 中置提取（纯 DSP，左人声/右伴奏）
                     └─ 计算机本地模型（demucs）
```

**四种组合 × 两种输入全部可用**，没有哪一种被禁用。切模块只换引擎那一组单选和
下面的参数框，切输入自动跳到对应的标签页。

### 界面外观（2026-10-14 重做）

原来是"能用的工程师风格"：白底、灰边框、七种模式平铺、硬编码颜色散落在三个
文件里（一共 45 处 `"#xxxxxx"`）。现在改成**深色仪器面板风**，配色和字体全部
收到 `host/theme.py` 一个文件里：

| 层 | 颜色 | 用在哪 |
|---|---|---|
| 窗口底 | `#16191f` | 根窗口，四周露出一圈当外框 |
| 内容区 | `#1e232b` | 卡片、面板、标签（**必须同色**，见下） |
| 次级 | `#262d37` | 输入框、按钮、标题栏、滑条槽 |
| 描边 | `#333c48` | 卡片边框、分隔线 |
| 强调 | `#5b9dff` | 数值、主操作、选中态、卡片标题 |
| 语义 | 绿/蓝/黄/红/灰 | 状态灯与告警，和 `status_panel.py` 共用 |

**为什么内容区必须一个颜色**：ttk 控件会把自己样式里的 `background` 画出来。
卡片用 `PANEL` 而里面的 `ttk.Label` 用 `BG` 的话，每个标签都会在卡片里留下一
块补丁。所以现在卡片不靠底色分层，靠**描边 + 强调色标题**，所有默认控件同色
无缝融合。

几处刻意的设计：

- **标题栏两个药丸徽章**（当前组合 / `sw` 值）用 Canvas 画圆角，改字走
  `set_pill_text`。踩过的坑：第一版把文字捕获在闭包里，一次 `<Configure>`
  重排就用旧文字重画，徽章永远停在创建时那个组合 —— 现在文字放在可变 dict 里。
- **频谱柱子带 2 px 亮帽**，是频谱仪的经典画法，比纯色矩形好读瞬时峰值，
  且只多一次 `create_rectangle`（渐变分段实测把绘制时间翻三倍，不值）。
- **左右声道不再用"深/浅"区分**：那是白底的规则，深色底下深的那半会糊进背景。
  改成同色系的"饱和（L）/ 淡（R）"，语义不变、两边都亮。
- **图例色块只画有数据的声道**：单声道源时画 L+R 两个色块会让人以为右声道也在显示。
- **灯板每盏灯带光晕**：Canvas 没有半透明填充，用一圈压暗的同色圆近似。
- **左栏参数面板可滚动**：高度随组合变化（最高那组 350 px），窗口矮的时候出
  细滚动条兜底，不裁卡片。滚动条只在需要时出现，平时不占位。
- **窗口高度按内容实测**：`_fit_to_content()` 把两个标签页各选一遍取最大值，
  再按屏幕收夹。写死 900 px 会把 Notebook 压成 115 px，「开始处理」按钮直接看不见。

`tool/verify_theme.py` 是这套外观的验收脚本，**不依赖截图**（锁屏也能跑）：
39 项图元检查（柱体四色齐全、亮帽、网格、边框、灯珠与光晕、文字数量）
+ 10 项 WCAG 对比度检查。深色主题最容易翻车的就是对比度，所以每条搭配都
有硬指标：主文本 ≥7:1、次文本 ≥4:1、弱文本（脚注/刻度）≥2.5:1。

实测结果：主文本 13.30、次文本 6.32、强调 5.80、告警 8.47、日志 7.05，全部达标。

| 组合 | 实时 | 文件 | 算法延迟 |
|---|---|---|---|
| 变调 × FPGA 直算 | ✅ | ✅ | 0（采样级） |
| 变调 × FPGA 内部小模型 | ✅ | ✅ | ≈30 ms |
| 分离 × 中置提取 | ✅ | ✅ | 21 ms（一个分析窗） |
| 分离 × 计算机本地模型 | ✅ | ✅ | **≈3 s**（块 1 s + 上下文 2 s，另有单块推理耗时） |

延迟是**如实报告**的：选到本地模型时，启动前会把这 3 s 写进日志和状态栏，
不会说成"实时"。demucs 缺依赖时会弹窗说明"将退化为直通"，由用户决定是否继续。

四种组合在两种输入下的输出语义（这一点必须说清楚，不能含混）：

| 组合 | 实时输出 | 文件输出 |
|---|---|---|
| 变调 × 任一副引擎 | 变调后的声音 | 变调后的声音 |
| 分离 × 中置提取（纯 DSP） | **左=人声 / 右=伴奏** | **左=人声 / 右=伴奏** + 可导出两条音轨 |
| 分离 × 计算机本地模型 | **左=人声 / 右=伴奏** | **左=人声 / 右=伴奏** + 可导出两条音轨 |

两种引擎、两种输入的**输出语义完全一致**（2026-10-20 改版）：
分离模块固定"一个声道一条音轨"，左人声、右伴奏，不再按男女分左右，
也不再"伴奏在两边原样保留"。这样四条波形（输入 L/R、输出 L/R）在
界面上各有明确含义，实时和文件听到/存出的东西也对得上。


> **格式支持是怎么来的**：`soundfile`（libsndfile）负责 WAV/FLAC/OGG/MP3/AIFF，
> `PyAV`（内置 ffmpeg）兜住 M4A/AAC/WMA/OPUS。两个都装上了才叫"常见格式都能读"。
> 装依赖：`pip install soundfile av`。打包成 EXE 时也必须用
> `--collect-all soundfile --collect-all _soundfile_data --collect-all av` 把它们带进去，
> 否则 EXE 只能读 WAV —— 这正是 2026-10-13 修掉的一个真问题（见下面"格式支持"一节）。

### 实时变声 / 文件变声（两种输入方式）

**实时**：麦克风 → 效果链 → 扬声器/耳机。

- **务必戴耳机**：外放会被麦克风重新采回去，形成啸叫。
- 输入设备、输出设备、采样率、缓冲块大小、输入增益都可现场调。
- **输入增益默认 +12 dB**：阵列麦克风原始电平普遍很小（本机实测 RMS 只有 0.0005），
  不放大的话变出来几乎听不见。觉得失真就往下调。
- 声卡本身延迟约 100~150 ms（1024 点 @48 kHz ≈ 21 ms/块 + 约 3 块预填充），
  算法延迟另算（见上表）。想要更低延迟就把块大小调到 512 或 256，但太小会开始爆音。
- 底部实时显示「缓冲块数 / 录音溢出 / 播放欠载」。欠载计数持续上涨说明机器跑不动，
  把块大小调大一档。
- 四种组合都能实时；切组合不用停止，下一个音频块就生效（参数改动不重置算法状态）。

**文件**：音频文件 → 效果链 → 新音频文件，可保存并回放。

- **输入格式**：WAV / **FLAC** / MP3 / M4A / AAC / OGG / OPUS / AIFF / WMA / AU / W64 / CAF …
  依次尝试 `stdlib wave` → `soundfile` → `PyAV(ffmpeg)` → `librosa`，谁先成功用谁。
  用哪个后端读的、原扩展名是什么，都会写在文件信息栏和日志里。
- **输出格式按扩展名决定**：`.wav`（16 bit PCM，默认）/ `.flac`（无损）/ `.ogg` / `.aiff`。
  认不出的扩展名会**写成真正的 .wav** 并把真实路径回显，不会把 WAV 数据塞进 `.xyz` 骗人。
- **载入时就把输入规整成双声道**：单声道文件复制到左右两路，>2 声道只取前两路。
  左右各跑一条独立效果链，输出永远是立体声。
- 文件模式走的是**质量最好**的那条实现（整段一次算完），不是实时那条流式链路：
  变调用离线 `hq_voice.process`，分离用 demucs / 中置提取整段处理。
  所以"实时听着什么样"和"文件存出来什么样"在算法上同源，但不逐比特相同。

### 内嵌播放器（文件页）

文件页处理按钮下面是一条常驻播放器，**不限制 15 秒，可以播完整首**：

| 控件 | 作用 |
|---|---|
| ▶ 播放 / ⏸ 暂停 | 从当前位置播放/暂停，暂停后再点继续 |
| ■ | 停止并回到开头 |
| 左 L / 右 R | **边放边开关**左右声道，互不影响，不会重新开始 |
| 进度条 | 拖动跳到任意位置（播放中也可拖） |
| 时间 | `当前 / 总长`，0.1 秒精度 |
| 音量 | 0~120%，默认 80% |
| 右侧标签 | 当前载入的是「变声结果」还是「原声」 |

- 处理完成后**自动把结果装进播放器**，点 ▶ 就能听。
- 「播放结果」重新把处理结果装回播放器；「试听原声」把原声装进去。
- 声道开关是在输出端乘增益（左/右各一个 0/1），不改缓冲区，所以
  关掉左声道再打开，右声道不会断音，进度也不跳。
- 播放器数据与 `proc_data` / `file_data` 共享同一块内存，不额外复制；
  正在播放的结果不会被缓存巡检释放。

实现：`host/player.py`（`Player` + `PlayerBar`），音频回调里按
左/右增益取样本，所以左右开关是**实时生效**的。

### 分离（模块）—— 左声道人声 / 右声道伴奏

`模块` 选 **「分离」**。默认引擎是 **中置提取（纯 DSP）**：
**左声道只出人声，右声道只出伴奏**。纯 numpy 实现，不需要任何模型、
不联网、不加依赖。

换成 **计算机本地模型** 时，人声前端从"中置提取"升级成 demucs 神经网络
（干净得多，一首歌要几十秒），**输出语义不变：左人声 / 右伴奏**。
**没装 demucs 时会明说并退回纯 DSP**，不会静默降级。

两个引擎的参数框里都有「声道路由」：可以一键切成
`人声→右 / 伴奏→左`（两个框共用同一个设置，选哪个都一样）。
「人声音量」「伴奏音量」分别调两路的增益，互不影响。

**可以导出两条音轨**：文件页勾上「同时导出人声 / 伴奏音轨」
（**仅「分离」模块下有效**），处理完会在输出文件旁边另外写两个文件
（扩展名跟随输出文件）：

| 文件 | 内容 |
|---|---|
| `<名字>_人声.<ext>` | 左声道的人声，单声道 |
| `<名字>_伴奏.<ext>` | 右声道去人声后的伴奏，单声道 |

> 需要**立体声源**（原理是"中置提取"，靠左右差异把人声和伴奏分开）。
> 单声道文件会自动降级成谐波提取并在日志里提示，效果会明显变差。
> 伴奏是"左右相加的一半再减人声"，所以硬声像（只出现在一侧）的伴奏
> 会衰减 6 dB；真实歌曲的伴奏通常两声道都有，不会这么明显。

### 分离 × 计算机本地模型 —— demucs 人声/伴奏

`模块` 选 **「分离」**，`引擎` 选 **「计算机本地模型（demucs）」**。
整条链路**全程在本机跑：不联网、不上传任何音频**。

```
输入混音
   │
   ├─ [神经网络]  demucs htdemucs 分离 ──▶ 人声 + 伴奏
   │
   ├─ [DSP]  人声处理（可选）
   │      内置高质量变调（相位声码器 + 共振峰保持）
   │
   └─ 重新混合（人声 / 伴奏音量分别可调）──▶ 输出
```

每一步是神经网络还是普通 DSP，都会原样打进日志——不想让人以为"AI 处理"
四个字下面全是神经网络。

- **实时也能用**，延迟 ≈ 3 s（块 1 s + 上下文 2 s，另有单块推理耗时）。
  这个数字会原样显示在参数框里，不会写成"实时"。
- **依赖是可选的**：`pip install demucs`（会带上 torch，CUDA 版约 4 GB，
  首次运行还会下载 80 MB 的 htdemucs 权重）。没装时参数框里会**写明缺什么**，
  实时启动前弹窗问是否以直通继续，文件模式则在日志里说明后按纯 DSP 跑。
  本机已配置好：torch **2.11.0+cu128** / torchaudio 2.11 / demucs 4.1.0，
  装在用户级 site-packages，文件夹版 EXE 也能直接用；详见
  [`AI环境配置说明_2026-10-20.md`](AI环境配置说明_2026-10-20.md)。
- **权重下载会自动绕开被墙的 huggingface.co**。demucs 4.x 走 huggingface_hub
  拉权重，国内直连经常在 SSL 握手阶段就失败，表现是"分离一直转圈然后失败"。
  程序启动时会检查：权重已在本地缓存 → 什么都不做（不联网、不耗时）；
  没有 → 用 HTTP HEAD 探测 `huggingface.co`，502/403 也算不通，
  自动把端点切到 `hf-mirror.com`。也可以在启动前自己设 `HF_ENDPOINT` 覆盖。
  ★ 这个切换必须在 import `huggingface_hub` **之前**完成
  （`HF_ENDPOINT` 是它 import 时读进常量的），所以放在 `host_app.py` 顶部。
- 有 CUDA 时自动用 GPU（本机 RTX 5070 Ti）；显存不够会自动缩短分段重试，再不够退回 CPU。
  本机实测：3 秒音频暖机后 **0.46 s（约 7 倍实时）**；首次调用含模型加载约 17 s。
- 「分离质量」三档：
  - 快速：段重叠 10%
  - 标准：段重叠 25%，**结果可复现**（同一输入跑两遍逐比特相同）
  - 高质：4× 耗时，做时间平移等变平均（demucs 官方说能提升约 0.2 dB SDR）

  这里刻意**不用** demucs 默认的 `shifts=1`：那个值只给输入加一次随机
  时间平移、不做任何平均，SDR 一点没涨，却让每次跑出来的结果都不一样。

客观验收见 `tool/verify_local_ai.py`（**30 PASS / 0 FAIL**）和
`tool/verify_stream.py --full`（**21 PASS / 0 FAIL**，流式与离线对拍）。
最关键的一条：合成一首"人声居中、但贝斯和底鼓也居中"的混音（真实歌曲就是这个样子），
demucs 的人声 SI-SDR **+18 dB**，而中置提取对照组只有 −0.07 dB——
**赢 18 dB**。这正是"必须用模型先验"的那一步，纯 DSP 做不到。

### 变调 × FPGA 内部小模型 —— 频域提质

`模块` 选 **「变调」**，`引擎` 选 **「FPGA 内部小模型（频域提质）」**。

| | FPGA 直算（时域延迟线，板上同款） | FPGA 内部小模型（频域 + 共振峰保持） |
|---|---|---|
| 做法 | 读一条延迟线，两个抽头交叉淡化 | 相位声码器伸缩 → 带限重采样 → 倒谱包络校正 |
| F0 | 变了 | 变了 |
| 共振峰 | **跟着一起变** | **留在原位** |
| 听感 | 升调后像小孩 / 花栗鼠 | 像"换了一个音域更高的人" |
| 时长 | 保留 | 保留 |
| 算法延迟 | 0 | ≈30 ms |
| 能否上板 | 能（就是 `rtl/pitch_shift.v`） | 不能（板上没有频域单元） |

原因是：延迟线把**整条频谱**按同一个比例 r 缩放，F0、谐波、共振峰一起搬。
而共振峰决定的是"声道有多长"，是音色而不是音高；把它也搬上去，就变成
"一个声道更短的人在说话" = 小孩声。

这一条**实时和文件都能用**：实时走 `hq_stream.StreamPitchShifter`（逐块进出，
块无关性逐比特一致），文件走离线 `hq_voice.process`（整段一次算完，质量更好）。
共振峰保持强度跟着界面滑条走——早期版本文件模式把 `formant` 写死成 1.0，
滑条动了输出没动，是个假控件，已修。

客观对照（`tool/verify_pitch_hq.py`，**17 PASS / 0 FAIL**，7 个场景）：

| 指标 | 时域延迟线 | 频域 + 共振峰保持 |
|---|---|---|
| 共振峰包络位移 | +500 … +1220 音分 | **±50 音分以内** |
| 包络与原始的相关系数 | 0.343 | **0.940** |
| 输出咔哒声（接缝） | ~500 处 | **0 处** |
| F0 误差 | ≤ 26 音分 | ≤ 26 音分 |

| 控件 | 默认 | 含义 |
|---|---|---|
| 音高偏移 | 0 半音 | −12…+12 连续可调；`sw[5:2]`（板上是 16 档离散值） |
| 共振峰保持 | 100% | 100% = 共振峰完全留在原位（不像小孩）；0% = 跟着音高走（就是普通变调）。仅对「FPGA 内部小模型」有效，直算引擎不读这一项 |

| 控件 | 默认 | 含义 |
|---|---|---|
| 分离深度 | 100% | 人声取出多少。100% = 全取出；调小 = 人声轨里留更多原混音，适合"只想稍微分一点" |
| 声道路由 | 人声→左 / 伴奏→右 | 可切成反向。两个参数框共用同一个设置 |
| 非谐波保留 | 20% | 中置成分里**不落在谐波齿上**的那部分保留多少。实测 20% 在齿音自然度和分离度之间最平衡 |
| 谐波梳状掩蔽 | 开 | 关掉就纯靠中置度，中置的贝斯/底鼓会被一起扣进人声 |
| 伴奏低频保护 | 120 Hz | 从伴奏里扣人声时，这个频率以下基本不扣，保住贝斯/底鼓。实测伴奏 SI-SDR 从 **−2.5 dB 提到 +9.4 dB**；0 = 关闭（全频段扣干净） |

| 控件 | 默认 | 含义 |
|---|---|---|
| 分离质量 | 标准 | 快速（重叠 10%）/ 标准（重叠 25%，可复现）/ 高质（4× 耗时，平移等变平均） |

| 人声变调 | +4.0 半音 | 只作用在挖出来的人声上，伴奏不动 |
| 共振峰保持 | 100% | 同上；人声变调走的就是「FPGA 内部小模型」那套频域算法 |
| 人声 / 伴奏音量 | 100% / 100% | 重混时各自的增益 |
| RVC 目录 | 空 | 放 `.pth` 的那一层。没有可用模型时界面会写明缺什么，不会假装能跑 |

只有「**变调 × FPGA 直算**」这一种组合能一对一招到板子上，`f_sw` 显示对应的

### 半音 ↔ 变调比 ↔ 拨码档位

`r = 2^(半音/12)`，`dphase = round(64×(r−1))`，`sw[5:2] = round(dphase/6) + 5`

| 半音 | r | 听感 | sw[5:2] 档位 |
|---|---|---|---|
| −12 | 0.500 | 降八度，恶魔低音 | 0 |
| −7 | 0.667 | 降五度，男声化 | 2 |
| −4 | 0.794 | 降大三度 | 3 |
| 0 | 1.000 | 原声 | 5 |
| +4 | 1.260 | 升大三度，女声化 | 7 |
| +7 | 1.498 | 升五度 | 9 |
| +12 | 2.000 | 升八度，花栗鼠 | 15 |

板子的 16 档每档相差 `6/64 ≈ 0.094`（约 1.6 个半音），所以有些半音值只能在软件里取到，
界面会自动显示最接近的那一档。

## 四路波形 / 频谱对照（右上）

2026-10-20 改版：默认显示 **四条独立时域波形泳道**，不再把左右声道挤在
同一格的两半里。

| 泳道 | 含义 | 颜色 |
|---|---|---|
| 第 1 条 | **输入 L** | 亮蓝 |
| 第 2 条 | **输入 R** | 淡蓝 |
| 第 3 条 | **输出 L** | 琥珀 |
| 第 4 条 | **输出 R** | 淡琥珀 |

每条的左侧直接标出该路当前的峰值 dBFS（`无信号` / `-16 dBFS`）。
四条**共用同一个量程**（右下角显示 `±0.292 FS` 这类值），所以"输出 R
比输出 L 低 12 dB"在图上就是真的矮一截，不会每路各自拉满造成误判。

- **分离模式**下看第 3、4 条：第 3 条（左）是人声，包络是断续的、
  跟着音节走；第 4 条（右）是伴奏，通常连续得多。
- **变调模式**下看输入/输出两条的周期疏密：升调后同一条泳道里的
  波形周期变短。
- 文件模式画的是整段包络（按像素列取 min/max），一屏能看到整首歌的
  结构；实时模式画最近约 4 k 点的滚动波形。

右上「视图」下拉可以切回原来的 **频谱对照**：

- 上（蓝系）= 输入，下（橙系）= 输出；每格左半 L（饱和色）/ 右半 R（淡色）
- 1024 点 FFT @48 kHz → 21 ms 一帧、46.9 Hz 分辨率
- 文件模式画整段 8 段平均谱；「显示」下拉支持 `同屏四路` / `只看左` /
  `只看右` / `平均`，只影响画图，DSP 始终四路独立。

**怎么用这两张图判断效果对不对：**

| 组合 | 波形 / 频谱上应该看到 |
|---|---|
| 变调 × FPGA 直算 | 频谱整条按比例平移，包络形状不变（+12 半音 ≈ 右移 8 格） |
| 变调 × FPGA 内部小模型 | 谐波齿间距变了，但**共振峰包络峰位几乎不动** |
| 分离 × 中置提取 | 波形：输出 L 断续（人声）/ 输出 R 连续（伴奏）；频谱：输出 L 是人声谱，R 保留低频与宽带伴奏 |
| 分离 × 计算机本地模型 | 同上，只是人声更干净、伴奏更完整 |
| 环形调制 / 回声 | 已从主面板撤下：边带 / 梳状齿，参数与测试仍在 |

## 状态校验灯板（右下）

16 盏灯，每 50 ms 全量刷新。颜色：绿=正常，蓝=进行中，黄=能用但有问题，红=阻断项，灰=未启用。

| 灯 | 判绿 | 判黄 | 判红 |
|---|---|---|---|
| 输入 / 输出设备 | 已选到设备 | — | 无可用设备，或缺 `sounddevice` |
| 采样率 | 输入输出一致 | 不一致 | — |
| 引擎 | 运行中（灰=已停止） | — | 停止且带异常 |
| 输入信号 | 峰值 > −34 dBFS | 偏低 / 静音 | — |
| 输出信号 | 有输出 | 无输出 | — |
| 输入电平 L / R | 无削波 | 偶发削波（< 20 次） | 持续削波（≥ 20 次） |
| 输出电平 L / R | 无削波 | 偶发削波（< 20 次） | 持续削波（≥ 20 次） |
| 缓冲 | 无丢帧 | 有抖动 | 丢帧严重 |
| DSP 内核 | 定点内核就绪 | — | 内核抛异常 |
| 文件链路 | 已载入 / 已输出（蓝=处理中） | — | — |
| 缓存 | 占用正常（显示 MB 与已清理次数） | 占用 > 200 MB | — |
| 板上档位 | 与 `sw[5:2]` 吻合 | 有偏差，或超出 16 档范围 | — |

**削波是按声道分开看的**：左右各自计数、各自点灯。只录到一侧过载、
或者两声道电平差得离谱，都会在灯板上直接暴露出来——混成单声道统计是看不出来的。
而且计数是**近期的**（每秒自动衰减 2 个），很久以前那次过载不会把灯永久钉在红色上；
累计值在日志里每 10 分钟报告一次。
「板上档位」这盏灯只在「**变调 × FPGA 直算**」下有意义：其余三种组合板子上
没有对应实现，灯会灰掉并显示「板上无此组合」。

灯板宽度不够时会自动减列加行，并把画布高度补上——不会像以前那样把最后一行裁掉。

灯板下面那行「建议」会把所有黄/红项的处理办法汇总成一句话
（比如"输入是静音：确认选对了麦克风"、"输出已削波：调小输出音量"）。

## 长时间运行 / 缓存自动清理

目标是"开着放几天也不出问题"。所有会随时间长大的东西都有上限或超时，
每 `30 秒`自动巡检一次（界面右下「缓存」灯和日志里都能看到它在干活）：

| 对象 | 策略 | 默认值 |
|---|---|---|
| 日志文本框 | 超过上限就从最旧的行开始丢 | 上限 400 行 |
| 处理结果音频 | 闲置超时后自动释放（可重跑再生），播放器随之卸载 | 闲置 10 分钟 |
| 已载入的素材 | 闲置超时后自动卸载（**处理中绝不卸载**），并在文件信息栏提示需重新载入 | 闲置 30 分钟 |
| 削波计数 | 按音频时长每秒衰减，很久以前的过载自动忘掉 | 2/秒 |
| 实时输入队列 | `Queue(maxsize=128)`，满了计入溢出而不是无限堆积 | 128 块 |
| 效果链残留缓冲 | 正常情况下只该有算法延迟那么多；超出 64 块就强制截断 | 防御性上限 |
| 分离器内部延迟线 | 每次推进后按绝对下标裁剪，只留基频分析窗需要的历史 | ≈1792 点 |
| 频谱分桶表 | 按采样率缓存，只有几个键 | — |

界面底部日志框上方有三个按钮：

- **立即清理缓存** —— 立刻裁日志 + 释放已经超时的结果/素材（不用等巡检）
- **清空日志** —— 日志清空
- **文件变声页的「卸载素材」** —— 立刻卸载载入的音频（自动卸载要等 30 分钟，这是手动版）

日志每 10 分钟打一条运行报告，内容是运行时长、缓存占用、已自动清理次数、
实时链路的缓冲/溢出/欠载和累计削波——挂机久了也能一眼看出状态是否健康：

```
[10:31:02] 运行 4 小时 12 分 ｜ 缓存 12.4 MB ｜ 已自动清理 3 次 ｜
           实时：缓冲 2 块 / 溢出 0 / 欠载 0 ｜ 累计削波 入 L0 R0、出 L3 R1
```

另外，文件处理进度的界面刷新按 1% 节流——以前每 8192 点就 `after()` 一次，
处理一小时的素材会往 tkinter 事件队列里塞两万多条回调，纯属没必要的负担。

## 格式支持（2026-10-13 修）

三个真问题，都是"看起来支持、实际不支持"：

1. **PyAV 分支早就坏了**。写的是 `frame.to_ndarray(format="fltp")`，
   而 PyAV 13 之后删掉了这个关键字参数 —— 于是每一种非 WAV 格式都抛 `TypeError`。
   现在改成 `AudioResampler(format="fltp")` 统一成平面 float32，
   不再依赖那个会随版本变的签名（同速率只做格式转换，FLAC 实测逐点保真）。
2. **报错报的是错的那个后端**。旧代码把 librosa 的 `No module named 'lazy_loader'`
   当成最终原因抛出去，把真正失败的 PyAV 完全盖住了，查都没法查。
   现在每个后端各自的原因都会列在 `AudioReadError` 里。
3. **打包没带解码器**（见上一节）。

另外顺手补的：

- **输出**支持 FLAC/OGG/AIFF（按扩展名选），不再写死 WAV。
- **写出时容错整型**：`save_audio`/`save_wav` 现在接受 int16/int32。
  之前传 int16 会按 float 写出去，±10000 被 clip 成满量程方波 ——
  文件照样生成、不报错，内容全错。分性别音轨导出正好会踩到这个。
## 算法一句话说明

**不需要 FFT。** 一条 4096 点延迟线上放两个相距 1024 点的抽头，抽头权重取自 Hann 窗
在该延迟位置的值。两个权重恒满足 `w(d) + w(d+1024) = 1`：

- 输出速率永远等于 fs → 时长不变
- 回绕处两个抽头互换角色 → 没有切换咔哒声
- 两个抽头的延迟同时以固定速率漂移 → 音高改变

详情见 `dsp_core.py` 里的注释和 `rtl/pitch_shift.v` 的头部说明。

## 分离原理（界面的 va 路由）

四步，全部在 numpy 里做，**没有模型、没有联网、没有新依赖**。

> 下面 1~3 步（中置提取、谐波梳、双基频估计）两种路由共用；
> 第 4 步是 va 路由的"人声 / 伴奏"分配。旧的 `route="mf"`
> （男左女右、伴奏两边保留）仍保留在代码里供回归测试，
> 但界面已经不再使用。va 路由的关键补充是**伴奏低频保护**：
> 从伴奏里扣人声之前先过 120 Hz 高通，否则贝斯/底鼓会被一起扣掉。
> 实测合成混音上伴奏 SI-SDR 从 −2.5 dB 提升到 **+9.4 dB**。

### 1. 中置提取

立体声混音里人声几乎总是居中（左右两声道几乎相同），伴奏则带有左右差异。
每帧做 STFT（1024 点 / 跳 256 / Hann 窗），用 mid / side 的幅度比算"中置度"：

```
mid = (L + R) / 2      side = (L - R) / 2
c   = clip((|mid| - |side|) / |mid|, 0, 1)
```

`c≈1` 表示这个频点在两声道里一模一样（人声，但也包括贝斯、底鼓），
`c≈0` 表示这个频点只存在于某一侧（立体声伴奏）。

另外还有一道**幅度门限**（相对本帧中置谱峰值 −35 dB）：中置度是个比值判据，
在没有能量的泄漏频点上比值毫无意义，不挡住的话硬声像伴奏的旁瓣会被当成中置成分。

### 2. 谐波梳状掩蔽

只靠中置度会把"居中且一直在响"的贝斯/底鼓也一起搬走。所以再用上一帧跟踪到的
基频 F0 生成一条谐波梳，只放行 F0 的各次谐波；齿与齿之间只放行「非谐波保留」那部分
（齿音、气声靠它保住）。梳齿是**平顶三角**而不是高斯——1024 点 FFT 的主瓣本身就有
2 根 bin 宽（@48 kHz 约 94 Hz），高斯梳会把自己的基频旁瓣削掉，实测纯音只剩 21 dB
抑制，改成平顶后恢复到 30 dB 以上。

### 3. 逐帧基频 → 男女判定

对提取出的人声做 60~1200 Hz 带通，归一化自相关找**第一个显著局部极大**
（不是全局最大：低频在小滞后处自相关本来就接近 1），得到该帧 F0 与浊音置信度。

F0 序列先做 9 帧中值滤波压掉颤音和倍频跳变，再用最近约 6 秒的浊音 F0 做**两类聚类**
（k-means，k=2）：两簇中心的中点就是这首歌当下的男女分界，钳在 130~240 Hz；
两簇分不开（只有一种性别）或样本太少时回退到 165 Hz。判定带 6% 迟滞，
另外有 150 ms 的 hangover——音节之间的空隙不会让人声一下子弹回中间。

### 4. 声像重定位（关键：不是"把伴奏也搬走"）

```
out_L = L - aL · v
out_R = R - aR · v
```

`v` 是从中置成分里提出来的**人声估计**，`aL/aR` 是"从该声道扣除多少"：

| 判定 | (aL, aR) | 结果 |
|---|---|---|
| 男声 | (0, 1) | 人声留在左，从右扣掉 |
| 女声 | (1, 0) | 人声留在右，从左扣掉 |
| 未判定/纯伴奏 | (0, 0) | 原样直通 |

因为 `v` 本来就是"两声道共有的那部分"，从另一侧扣掉它以后，
**伴奏（= 左右各自减去 v 剩下的部分）在两个声道里一点没动**，人声则只出现在一侧。
判定翻转时有 30 ms 线性交叉淡化。

流式实现：帧网格锚定在绝对样本下标 `k*HOP` 上，与调用方怎么分块无关，
所以分块 1024 / 8192 / 整段的结果逐点相同（验收脚本里有这一项）。
算法延迟 1024 点（48 kHz 下 21 ms），但**输出内容与输入逐点对齐**。

## 已知限制

1. **降调超过约 9 个半音，误差会变大**。这是时域变调器的固有性质：两个抽头相距 1024 点，
   对低频输入相位不相干，交叉淡化会产生包络起伏。实测全 25 档最大误差 2.25%（−11 半音处），
   −8 半音以内误差 < 0.5%。要更低就得加长延迟线（改 `AW`）。
2. 约 1% 的系统性偏低来自分数延迟的线性插值低通效应，听不出来。
3. 实时模式用的是「两条独立流 + 队列」而不是 duplex stream：Windows 上麦克风和耳机
   常挂在不同的 host API，强行 duplex 会直接报 PortAudio 错。代价是多一点延迟。
4. **分离需要立体声源**。中置提取靠的是左右差异，单声道文件没有 side 信息，
   只能退化成纯谐波提取（代码会自动识别并降级，界面上也有提示）。
5. **合唱/多人同时唱时人声掩蔽会抖**。一帧只估两组 F0，要真正分开需要
   多 F0 估计或者神经网络，那就不止一个 numpy 了。
6. **人声本来就不在中间的混音效果会差**。比如人声被刻意调到一侧的歌。
7. **中置的乐器会被带着走**。谐波梳只能挡住"不跟人声同谐波"的那部分；
   与男声基频重合的贝斯会被一起算进人声。界面上的「伴奏低频保护」
   （默认 120 Hz）就是专门用来把贝斯/底鼓夺回伴奏的；还可把
   「非谐波保留」调大、或把「分离深度」从 100% 降下来。
8. 分离模式两端各 21 ms 内不做声像搬移（分析窗在信号两端必然被截断，
   强行提取会往结尾塞一段伪人声，实测 0.05~0.10 电平）。听不出来。
9. **「分离 × 计算机本地模型」实时延迟约 3 秒，能实时但不是零延迟**。
   demucs 按块流着算，一块 1.0 s + 重叠上下文 2.0 s ≈ 3.0 s 才有输出；
   文件模式是整段离线算完，质量最好。同一条信号两种输入下流式与离线
   质量已实测追平（`tool/verify_stream.py --full`，SI-SDR 18.26 / 24.31 dB），
   但**听感上实时模式就是会慢三秒**，界面在启动时和参数框里都会写明这个数。
   「变调 × FPGA 内部小模型」实时延迟约 30 ms，接近无感。
10. **打包出来的单文件 EXE 里没有 torch**。这不是偷懒，是实测之后的取舍：
    torch cu128 全套 **4.2 GB**（`torch_cuda.dll` 774 MB、`cublasLt64_12.dll`
    643 MB、`cudnn_engines_precompiled64_9.dll` 459 MB …），而且
    `tool/probe_torch_dlls.py` 实测**这些 DLL 在 torch 初始化时被全部加载**，
    能省的只有 47 MB 的 `.lib`（本来就不打包）—— 精简路线走不通。
    打进去的结果是：EXE 4 GB+，每次启动解压几分钟，完全不可用。
    所以 EXE 里选「分离 × 计算机本地模型」时，参数框会写明"缺少 torch、demucs"
    并**直接指明出路**（用 `host\运行上位机_AI完整版.bat` 启动），
    **其余功能不受影响**。

    要用完整 AI 就双击 **`host\运行上位机_AI完整版.bat`**：它会先自检
    torch / demucs / CUDA / 权重缓存，全绿才启动，缺什么告诉你装什么。
    本机实测（RTX 5070 Ti Laptop，11.9 GB）：20 秒音频分离 **3.10 s
    （6.5 倍实时）**，显存峰值 781 MB。
11. **合成音频在 demucs 眼里未必是人声**。验收脚本里第一版合成的"人声"是
    稳态谐波堆，被判给了 `other` 源。补上 5.5 Hz 颤音之后才判对
    （SI-SDR 从 −23 dB 变 +23 dB）。真实录音没有这个问题，但如果拿合成
    音源测试 AI 分离，记得给基频加抖动——**恒定的基频就是合成器的特征**。


`verify_engine_chain.py` 是这套三级结构的总验收，盯的是三件事：

- **分发对不对**：四种（模块 × 引擎）组合分别落到 `VoiceChain` /
  `StreamPitchShifter` / `VocalSplitter` / `StreamSeparator`，音高与分离
  方向各自量对（+4 半音 fpga_direct 282.4 Hz / fpga_model 280.7 Hz；
  男声 110 Hz 左 RMS 0.241 右 0.057，女声 231 Hz 左 0.067 右 0.326）。
- **不反复重建**：比值不变时 `set_ratio` 必须立刻返回——实时链路每个音频块
  都会配一次参数，一旦顺手 `reset()` 就把算法打回预热静音段（实测 24 块全零）。
  脚本用"每块都配"和"只配一次"两种驱动方式对比，稳态段差必须为 `0.000e+00`。
- **降级路径也返回 int16**：缺 demucs 时 `split × local_model` 走降级直通，
  这一路早期返回 float32，被 `to_float` 一 cast 变成 0/±1 方波（全程静音）。

`verify_pitch_hq.py` 的关键设计：激励是**直接给谐波幅度赋值**的元音
（谐波幅度 = 三个洛伦兹共振峰的叠加），所以"频谱包络就是设定的峰位"，
变调前后的相对变化才有可比性。早期版本用"锯齿声源 + 并联谐振器"，
测出来的峰位跟设定值对不上（设定 730/1090/2440，实测只找到 1125/2438），
"共振峰漂移"这个指标当时根本没有意义。

`verify_local_ai.py` 的关键设计：

- **对照组是中置提取**，而且测试混音里**贝斯和底鼓也居中**（真实歌曲就是
  这样）。这样"中置提取必然失败"就成了 demucs 的对照组，而不是让它和
  空气比。
- **激励必须带颤音**。第一版的稳态谐波堆被 demucs 判给了 `other` 源
  （SI-SDR −23 dB），补上 5.5 Hz ±3% 颤音后才判对（+18 dB）。
  `tool/exp_demucs_vocal.py` 就是做这个归因实验的脚本，留着了。
- **变调量另外用基频主导的稳态音测**。带颤音的信号用自相关测 F0 会八度
  跟错（~230 Hz 测成 527 Hz）；"谐波梳在对数频率轴互相关"也不行
  （梳子有八度周期性，+12 半音被判成 +4 音分）。所以分层：算法精度用
  稳态元音（`verify_pitch_hq`），接线正确性用基频主导的谐波音。

## 与 FPGA 版的关系（2026-10-11 更新）

FPGA 那边的硬件已经确认：**板载 codec 是 ES8388，跑在主模式，实际采样率 24.414 kHz**
（MCLK = 50 MHz/4 = 12.5 MHz，codec 内部分频 512 得到 LRCK）。

两边用的是同一套算法与同一套参数含义，但有两个地方因为采样率不同而不等价：

| 项 | PC 上位机 | ACX720 板 |
|---|---|---|
| 采样率 | 声卡决定，通常 44.1 / 48 kHz | 固定 24.414 kHz |
| 变调档位 | GUI 滑杆，半音为单位 | 拨码 `sw[5:2]`，每档 6/64 ≈ 1.6 半音 |
| 回声 `taps` 每档延迟 | 256 点 ≈ 5.3 ms @48k | 256 点 ≈ 10.5 ms @24.4k |
| 输入增益 | GUI 里的「输入增益」滑杆 | 由 ES8388 寄存器决定，需改配置表 |

也就是说：在上位机里调好的**效果类型、变调半音数、环形调制频率**可以直接搬到板上；
**回声的延迟时间**在板上会翻倍，介意的话把 `taps` 减半。

**男女声分离在板子上没有对应实现**，这不是偷懒：板子读不了音频文件，
而且逐帧基频估计 + 谐波掩蔽远不是 7 系列放得下的规模。板子那边这次同步补的是
**左右声道各自的电平/削波统计与立体声相关性指示**（`rtl/stereo_meter.v`），
也就是把"左右确实在分别运算"变成 8 颗 LED 上看得见的东西。

板上参数怎么拨，见 [`../README.md`](../README.md) 第 4 节的拨码对照表；
GUI 右下角也会实时显示当前参数对应的 `sw` 十六进制值。
