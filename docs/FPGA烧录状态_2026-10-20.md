## “Vivado 不支持 xc7a35t”是怎么回事

Vivado 2026.1 的**工程/综合器件库**已经移除了 7 系列：

```
get_parts *7a35*   ->  NO_PART_MATCH
get_parts xc7a*    ->  count=0
```

但这只影响**新建工程、综合、实现**，**不影响 Hardware Manager 烧录**。
Hardware Manager 仍然通过 JTAG IDCODE 识别到了芯片：

```
targets: localhost:3121/xilinx_tcf/Digilent/210251A08S14
DEV: xc7a35t_0
  PART = xc7a35t
  IDCODE = 00000011011000101101010010010011
```

现在装了 **Vivado 2023.2**，它原生支持 7 系列，综合/实现/烧录都可以用。

> 注：日志里 `3 ILA core(s)` / `Unable to find Debug Probes file` 是
> 芯片里上一次工程残留的调试核提示，和本次 bit 无关；本次 bit 没有
> ILA。`End of startup status: HIGH` 才是烧录成功的判据。

## 本轮 RTL 是否需要重新综合？

**不需要。** 四路波形、内嵌播放器、人声/伴奏分离都是 PC 上位机侧功能；
RTL 的变调/环调/回声、I2S、SPI 镜像没有改。19:10 的 bit 就是当前 RTL 的
最新实现。

## 复烧 / 换 bit 的步骤

1. 板子上电，JTAG-HS2 接好（设备管理器里 FTDI 设备正常，无感叹号）。
2. 双击 `tool\烧录FPGA.bat`，或运行上面的 Vivado 命令。
3. 看到 `End of startup status: HIGH` 即成功。
4. 若换 bit 文件，改 `program.tcl` 的 `BITFILE` 或传参：
   `vivado -mode batch -source tool/program.tcl -tclargs path\to\xxx.bit`

## 备注：COM3

`COM3` 是 CH340 串口（STM32 的 USART1 日志口），不是 FPGA 配置口。
本次检测时 COM3 在 9600~921600 **全部无数据**，说明 STM32 固件没有在
打印，或 PA9(TX) 没接到 USB-TTL 的 RX。烧录走的是 Digilent JTAG，
和 COM3 无关。
