# 杂音的真凶：过期比特流（2026-10-23）

> 结论先行：**喇叭里的杂音不是 DAC、不是滤波、不是变调算法，而是板子里跑的是
> 一份比源码旧一天的比特流。** `spi_mirror_tx.v` 在 2026-10-20 深夜把 CS̄ 从
> "每字一个脉冲"改成"每帧一个脉冲"，但 `vivado_prj/voice_changer.bit` 是改动
> **之前**（10-20 23:23）综合的。结果 STM32 的 EXTI4 每个字都触发一次，
> `g_side` 永远被清 0，几乎从不写 DAC —— 输出长期停在旧样值上，偶发刷新时
> 拿到的是左右错位的两个字。听感就是"**只有有声音的时候才有的沙沙/电流声**"。

用户当时说的是"我就是直通档"，这句话很关键：直通档在 RTL 里是
`dout <= din`（`voice_proc.v` 的 default 分支），**不经过任何算法**。
所以上一轮把杂音归因于"变调算法的 5~9 dB 调幅"是错的（那是变调档的事）。

---

## 1. 为什么这个 bug 特别难看出来

链路上每一层自检都是绿的：

| 检查 | 结果 | 说明 |
|---|---|---|
| PC 侧重采样纯度 | THD **−87 dB** | `CABLE Output → StreamResampler → 24.414 kHz` 逐样本干净 |
| FPGA 帧解析 | **1143/1144 = 100%** | CRC 全对，FIFO 每帧都进 64 个样本 |
| STM32 收字速率 | **48 783 字/秒** | 理论 48 828，差 0.1% |
| 寄存器 | `SPI2_CR1=0x0B54` `GPIOB_CRH=0xB4B34444` `RCC_CFGR=0x0038040A` | 全部正确 |
| 门控 ON−OFF | +25.9 dB | "有声音" —— 但 1500 Hz 对照也涨 +25.7 dB |
| **门控对照判据** | **FAIL** | ★ 这正是线索：涨的是宽带噪声，不是 1 kHz 纯音 |

"有声音"其实是"有噪声"。上一轮之所以判 PASS，是被 +25.9 dB 这个数字骗了。

## 2. 怎么把它钉死的（四步，每步都可复现）

### 2.1 先把 PC 侧排掉

```
python tool/probe_bridge_dsp.py 1000 0.5
→ f0 1000 Hz，H2 −102 dB，H3 −98 dB，THD(2~8) −87 dB，分段 1 kHz 以上全在 −50 dB 以下
```
PC 侧（采集 + 重采样 + 成帧）完全干净，问题必然在 FPGA 之后。

### 2.2 再看 FPGA 收到没有

```
python tool/fpga_uart_echo_check.py COM5 --seconds 3
→ frames_sent=1144 bytes_read=1143 0xA5=1143 → RESULT: PASS
```
每帧回 1 字节说明 CRC 全过、FIFO 也确实写进去了。

### 2.3 关键一步：把 MCU 收到的样值抓出来看

给固件加一个 `-DCAPTURE` 诊断构建（`main.c` 里的环形缓冲，1024 对），
用 OpenOCD 读回来：

```
python tool/probe_inject_pcm.py --const 0x1234 --secs 20     # 灌已知值
（另开一个窗口）openocd … mdw 0x20000020 1024                # 读回
```

旧比特流下的结果：

```
捕获环 1024 对，L/R 唯一值都只有 1 个：7572（全一样，但不是我们灌的 4660）
g_words   = 6 284 854        （48.8k 字/秒，正常）
g_cap_wr  =    26 599        （只占 1/118 —— 左右配对几乎从不成立）
```
`g_cap_wr` 只在"右声道分支"里自增。它比 `g_words` 小两个数量级，说明
**几乎每个字都被当成了左声道**。而 `g_left` 只被写、不参与 DAC 刷新，
DAC 就长期停在一个旧值上。

把 CS̄ 的 EXTI 计数也加上以后（`g_edge` / `g_left_n` / `g_cap_wr`）：

| 计数器 | 旧比特流 | 新比特流 | 说明 |
|---|---|---|---|
| `g_edge`（EXTI4 次数） | 与字数同量级 | **24 390/s** | 每帧一次才对 |
| `g_left_n` | ≈ g_words | 24 391/s | 每帧一次 |
| `g_cap_wr` | 1/55 ~ 1/118 的字数 | 24 389/s | **1:1 了** |

### 2.4 时间戳对账（最省事的一步）

```
vivado_prj/voice_changer.bit          2026-10-20 23:23
rtl/spi_mirror_tx.v                   2026-10-21 01:01   ← 比 bit 新 1.6 小时
```
`spi_mirror_tx.v` 的文件头就写着"★ 2026-10-20 改：CS̄ 从每字一个脉冲改成
每帧一个脉冲"。改动没进比特流。

| # | 文件 | 改动 | 作用 |
|---|---|---|---|
| 1 | **重新综合并烧录比特流** | `rebuild_FPGA.bat` → `烧录FPGA.bat` | ★ 根因修复 |
| 2 | `mcu/f103_spi_mcp4922/main.c` | OVR 清除改成"先读 DR 再读 SR"（RM0008 的顺序），并补 `g_side=0` 重新对齐 | 原来 OVR 清不掉 → 中断线常亮 → ISR 死循环，`g_words` 冻住、`g_ovr` 每秒涨 4.9 万。**只要用调试器 halt 一秒就会踩到**，表现是"读一次计数器之后声音就没了" |
| 3 | `tool/fpga_audio_bridge.py` | 开播前预灌 8 帧（512 点 ≈ 21 ms）到 FPGA FIFO，缓冲上限从 8 帧提到 12 帧 | FPGA 的 FIFO 从 0 起，而 PC 与 FPGA 的名义速率相等 → 水位永远贴着 0，CH340 的 16 ms USB 延迟一突发就欠载（`hold last`）→ 又是"只在有声时听得见"的断续。预灌把水位垫到 21 ms |
| 4 | `tool/check_bitstream_fresh.py` + `烧录FPGA.bat` | 烧录前比对 `.bit` 与 `rtl/*.v`、`constr/*.xdc` 的时间戳，过期直接 ABORT（`--force` 可跳过） | 防呆：这个坑不能再踩第二次 |
| 5 | `tool/rebuild_bitstream.py` + `rebuild_FPGA.bat` | 综合→实现→写 bitstream→**自动复制成 `vivado_prj/voice_changer.bit`**（旧的先备份） | 原来最后一步手工复制，漏掉就"跑完了、没报错、烧进去还是旧逻辑" |

## 5. 剩下的 −27 dB 是什么（不是 bug）

修完之后 THD 的构成：**H3 −27.2 dB 主导**，H2 只有 −45.0 dB。
三次谐波主导 = 对称非线性 = 功放/喇叭被推得比较满，不是削波（削波会先出
一堆高次谐波），也不是数字域（数字域在 12~22 kHz 那段已经是 −33 dB，
和 PC 扬声器的 −34 dB 一样干净）。

做了一组衰减对照（固件 `-DOUT_ATTEN_SHIFT=n`，以 2048 为轴衰减，静音电平不动）：

| 数字衰减 | 麦克风 RMS | THD |
|---|---|---|
| 0 dB | −16.7 dB | −27.1 dB |
| −6 dB | −25.9 dB | −28.3 dB |
| −12 dB | −38.8 dB | −18.1 dB（**已到麦克风底噪，不成立**） |

THD 随电平几乎 1:1 变化 → 是**与电平成正比的三次非线性**（小喇叭的固有失真），
降电平只能等比例换来"更小声所以更干净"，不能把比例降下去。
默认用 0 dB（单位增益）；嫌吵/嫌毛就把 PAM8403 的电位器或系统音量调小，
或者用 `-DOUT_ATTEN_SHIFT=1` 编一版（−6 dB，实测 THD −28.3 dB）。

## 6. 每次上电的操作顺序（务必按这个来）

1. **`tool\烧录FPGA.bat`** —— 板子每次掉电都要重烧（bitstream 只写 SRAM）。
   现在这个脚本会先检查 `.bit` 是不是比 RTL 旧，旧了直接拒绝并提示重建。
2. `tool\启动FPGA声卡桥.bat`（或上位机里点"一键启动"）。
3. 上位机「输出设备」选 `CABLE Input (VB-Audio Virtual Cable) [Windows WASAPI]`。
4. 板子拨码 `sw[7:6] = 00`（直通）先验通路，再调到别的效果档。

改了 `rtl/` 或 `constr/` 里**任何**东西之后，必须先
`tool\rebuild_FPGA.bat`（3~8 分钟），再烧。不要直接烧旧的 `.bit`。
