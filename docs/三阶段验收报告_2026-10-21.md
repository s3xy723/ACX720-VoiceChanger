## 2. 阶段二：AI 分离精度

### 2.1 先给结论

用户点名的三类可能原因，逐一查完：

| 可能原因 | 是否成立 | 依据 |
|---|---|---|
| **模型参数**（shifts / overlap / segment） | ❌ 不是瓶颈 | 见 §2.4：模型档位与分段在合理区间，非法参数组合已被 `_model_segment` 夹住 |
| **前后处理**（WOLA 归一化、增益、flush 顺序） | ✅ **成立，已修** | §2.2 的 WOLA 双归一化（-3.5 dB） |
| **采样率匹配** | ❌ 不是瓶颈 | 纯 44.1k↔48k 往返 **+48.6 dB**；44.1k 与 48k 两路的重建质量只差 **0.11 dB** |

真实缺陷只有 2 个（WOLA 双归一化、八度歧义），都已修复并量化验证。

### 2.2 缺陷一：`extract_center()` 的 WOLA 双归一化（-3.5 dB 固定衰减）

```python
# 修复前
acc = (L + R) * 0.5 * _OLA      # _OLA = 2/3
# 而 _OLA = 2/3 本来就是"Σw² 稳态 = 1.5 ⇒ 除以 1.5"的结果
```

`_OLA` 这个常数本身就是"Σw² 稳态值 1.5 取倒数"得来的。代码里既乘了 `_OLA`、OLA 内部又除了一次 Σw²，等于**除了两次 1.5**。

- 实测纯居中信号增益：**0.665**（恰好 2/3，即 -3.5 dB）
- 修复后：**1.00**

这类缺陷听感上是"开了分离就整体小声一点"，很容易被误当成"模型输出本来就弱"。

### 2.3 缺陷二：自相关基频的八度/半频歧义

ACF 在 `f0/2` 和 `2×f0` 处同样会出峰。原来的实现在候选里挑一个显著度最高的，于是：

- **独唱女声**：基频被判成半频，人声能量被分到男女两轨 → 女声轨能量份额仅 **0.484**
- **真八度齐唱**（男 118 Hz + 女 232 Hz ≈ 2×118）：如果按"显著度二选一"折叠，齐唱会被误杀

第一版修复（按显著度二选一）的代价很直观：

```
        修复前      第一版修复后
男声轨   -10.02 dB   -9.15 dB
女声轨    -0.94 dB   -3.32 dB
```

差到不能接受。改成**物理判据**后：

> 两候选成 2:1 时，仅当**低候选处没有谱峰**（说明它是半频假峰）才丢弃低的取高的；低候选处有能量则不动（可能是真八度齐唱，折叠的代价不对等）。

结果：A/B 测试与关闭折叠**完全一致**（不伤害齐唱场景），而独唱场景女声轨能量份额 0.484 → **0.862**。

### 2.4 采样率匹配的量化结论

新增 `tool/verify_sep_samplerate.py`，用**不依赖素材真实性**的硬指标：

```
--- 对照组：纯 44.1k→48k→44.1k 往返（不过模型） ---
  往返 SI-SDR = +48.62 dB

--- 44.1k 原生（无重采样） (8.0 s) ---
  等长=True (352800/352800)  有限=True
  能量守恒 (人声+伴奏)/输入 = 1.006
  重建恒等式 人声+伴奏 vs 输入 = +39.00 dB

--- 48k 输入（内部往返重采样） (8.0 s) ---
  等长=True (384000/384000)  有限=True
  能量守恒 (人声+伴奏)/输入 = 1.005
  重建恒等式 人声+伴奏 vs 输入 = +38.90 dB

=== 采样率匹配结论 ===
  重建恒等式：44.1k +39.00 dB  vs  48k +38.90 dB  （差 -0.11 dB）
  OK：48k 与 44.1k 的重建质量基本持平，采样率匹配不是瓶颈
```

**为什么"重建恒等式"是最强的判据**：把 4 个 stem 加起来必须还原输入。这一条把重采样、归一化、split/overlap、shifts 全部串在一起验了 —— 任何一处漏增益或错位，4 轨就加不回输入。+39 dB 说明这条链路是干净的。

### 2.5 方法学教训（重要，已作废一个旧结论）

**之前报过的"44.1 kHz 原生下人声 SI-SDR +21.63 dB"是假信号，此处作废。**

原因：本机没有任何真实人声录音，只能用合成信号。而把纯合成的类人声单独送进 htdemucs，4 个源的能量占比是：

```
drums 0.2%   bass 0.0%   other 99.8%   vocals 0.0%
```

**demucs 的人声检测器根本不认合成音。** 此时"人声轨"拿到的是接近 0 的残差，拿它去算 SI-SDR 就是在噪声上做比值 —— 数字会在 **-65 dB 到 +23 dB** 之间乱跳，与代码对错无关。

测试信号本身也踩了两次坑：

1. 第一版包络是"整体指数衰减 tau=0.35 s"，5 秒以上的信号里"人声"只有开头 1 秒有声、后面全静音 → SI-SDR 直接失去意义。改成**持续的音节串**后能量守恒从 1.02 回到 1.005。
2. 第二版是纯谐波堆叠，被判成 `other`（像合成器 pad）。改成**源-滤波器模型**（声门源 k^-1.4 × 三个时变共振峰 × 音节包络）后仍然不被认作 vocals —— 所以最终放弃用合成素材谈绝对 SI-SDR。

**要在真实录音上得到绝对精度，需要用户提供一段带人声的音乐。** 有了真值（或人工标注）才能算真正的 vocal SI-SDR。

### 3.2 数据收发正确性 —— ✅ PASS

判据设计是关键：FPGA 每收到一个 **CRC 正确的帧**就回一个字节 `0xA5`，所以要区分两种"收到数据"：

| 现象 | 字节数 / 发帧数 | 结论 |
|---|---|---|
| 真回显（FPGA 在工作） | ≈ **1.0** | PASS |
| TX/RX 短接的本地回环 | ≈ **261**（整帧被弹回） | FAIL |
| 基线静听（不发数据） | 0 | 若 >0 则判 INCONCLUSIVE（有别的设备在说话） |

实测：

```
第一轮  762 帧发送 → 762 字节回显   （比例 1.000，全部 0xA5）
第二轮 2288 帧发送 → 2288 字节回显  （比例 1.000，全部 0xA5）
基线静听 0.5 s → 0 字节
6 秒压力持续发送 → 无丢帧
```

**结论：链路是通的，CRC 校验在跑，不是本地回环。**

### 3.3 协议错配的发现与修正

审查时发现一个致命的不一致：

- 顶层烧进 FPGA 的是 `rtl/spi_mirror_tx.v` —— 输出的是 **SPI** 时序（SCK / CS̄ / MOSI）
- 而 `mcu/i2s_stereo_dac.c` 是按 **I2S 从机**写的（WS / BCLK / SD）

两者引脚定义和帧结构完全不同，接上去必然没声音或全是噪声。已重写为 SPI2 从机驱动并同步改 RTL：

**`rtl/spi_mirror_tx.v` 时序重写**

| 项 | 旧 | 新 |
|---|---|---|
| CS̄ 周期 | 每**字**一个下降沿 | 每**帧**（左+右）一个下降沿 |
| 帧周期 | — | 2048 周期 = 24.414 kHz（`CNT_CS_HI=32` / `CNT_SLOT=1008` / `CNT_ACTIVE=384` / `PHASE_BIT=24`） |
| 分频实现 | 取模（综合出真除法器） | 纯比较器切分 `in_slot0/in_slot1` |
| 发送中的样本 | 可能被中途刷新 | 每个字槽前锁存 `word_r <= tx_left/tx_right` |
| 接线 | PA4/PA5 被 SPI1 占用 | 改 PB13/PB12/PB15（SPI2），PA4/PA5 留给 DAC |

Vivado 2023.2 `xvlog` 编译通过，无 error。

### 3.4 音响驱动重新设计

#### 3.4.1 原驱动的四个硬伤

| # | 硬伤 | 后果 |
|---|---|---|
| 0 | **从来没人配过系统时钟** | 复位默认 HSI **8 MHz**，而 TIM6 的 ARR 是按 72 MHz 算的 → 实际帧率 **2.7 kHz** 而不是 24.4 kHz，慢了 9 倍。表现就是"能出声但完全听不清"，且怎么调音频参数都没用。**这是"驱动不好用"的第一嫌疑** |
| 1 | 每个字进两次 RXNE 中断（≈97.6 k 次/秒） | F103 @72 MHz 光进出栈就吃掉一大截 CPU，叠加串口打印必然 OVR 溢出，声音断续、爆音 |
| 2 | 左右声道靠"第一个是左、之后交替"推断 | 丢一个字就**永久左右颠倒**，复位也未必救得回来 |
| 3 | 完全没有缓冲水位调节 | 两侧晶振差几百 ppm，长时间跑必然周期性欠载/溢出，每隔几分钟"咔"一下 |

#### 3.4.2 新方案

`mcu/spi2_dma_dac.c`（重写）：

- **`clock_init()`**：HSE 8 MHz ×9 → 72 MHz；HSE 起不来退 HSI/2 ×16 = 64 MHz（ARR 是宏，自动跟着变）。FLASH 2 等待周期 + 预取。
- **SPI2 从机 + DMA1_Channel4 循环接收**：中断从 ~97.6 k/s 降到 **~95/s**（512 字缓冲，半满/全满各一次）。
- **EXTI12 抓 CS̄ 下降沿做帧同步**：丢字只烂当前一帧，不累积。恢复动作是"若 `(已收-已消费)` 为奇数则 `rd++` 凑偶"，下一帧立刻正确。
- **写指针 `dma_wr_now()`**：中断只维护 `g_cycles`（TCIF4 锁存，一轮一次），用时现算 `g_wr = g_cycles*RB_WORDS + (RB_WORDS - CNDTR)`。
- **速率自适应**：整帧对齐地丢帧/补帧（一次动 **2 个字**），水位钉在 `mid ± 64`。
- **上电自检提示音**：1 kHz 三角波 0.25 s（`DIAG_BEEP`），以及连续 3 s 收不到数据的周期性"嘀"一声（`DIAG_NODATA_BEEP`）—— 用来二分"FPGA 没送"和"DAC 没出"。
- **ARR = 2948**（72e6/2949 = 24415.06 Hz，**+41 ppm**）。写成 2949 会变成 24406.78 Hz（**-298 ppm**，每秒要补 7 帧）。

#### 3.4.3 验证结果 —— ALL PASS

`tool/verify_mcu_dac_driver.py` 把 C 里的核心算法逐行移植到 Python，喂真实波形逐样本跑（本机没有 ARM 编译器，验逻辑不验语法）：

```
[4] DAC 量化 / DHR12RD 打包 / 提示音波形          6 PASS
[1] 正常链路：左右逐样本一致                       3 PASS  （码值差 0）
[2] 丢一个字后左右归位（含旧方案负对照）            2 PASS
[5] 写指针量化（负对照）                           3 PASS  （量化版 hold 4896/20000）
[3] 晶振漂移 +1000 ppm                            3 PASS  （水位波动 0 字）
[3] 晶振漂移 -1000 ppm                            3 PASS  （水位波动 0 字）
                                         汇总：ALL PASS
```

±1000 ppm 的实测细节：

```
+1000 ppm：水位 2..322 / 512，over=0 under=0 starve=0
           后半段波动 0 字；16 s 内丢 310 帧、补 95 帧，平均每 39.5 ms 一次
-1000 ppm：水位 0..192 / 512，over=0 under=0 starve=0
           后半段波动 0 字；16 s 内丢 0 帧、补 502 帧，平均每 31.9 ms 一次
```

每次校正只挪动一个 **41 µs** 的帧，对音乐和语音都听不出来。

三条负对照的作用（防止以后把修复改回去）：丢字后左右颠倒 376/379、量化写指针 hold 4896/20000、提示音波形写反成 `v/32768*amp` 会整段塌成 0。

#### 3.4.4 补齐可编译骨架

原工程只有裸 C，**拿到编译器也编译不出可运行的固件**（缺向量表、缺 `.data/.bss` 初始化、缺链接脚本）。已补齐：

| 文件 | 作用 |
|---|---|
| `mcu/f103_startup.c` | 向量表（含 `TIM6_IRQHandler` 在第 **70** 项、`EXTI15_10` 第 56 项、`DMA1_Ch4` 第 30 项）+ `Reset_Handler`（.data 搬移 / .bss 清零） |

### 4.1 ⚠️ 端到端发声未实测（阶段三-3）

**状态**：链路各段都已单独验证通过，但"PC → COM4 → FPGA → SPI → STM32 → DAC → 音响"的实际发声**没有跑过**。

**阻塞原因**（两个都必须解决）：

1. FPGA 需要重新综合并烧录 —— 顶层 `spi_mirror_tx.v` 的 CS̄ 时序在本次改动中从"每字"改成"每帧"，旧 bit 与新固件**不兼容**。
2. STM32 需要重新编译并烧录新固件 —— 本机**没有 ARM 交叉编译器**（`arm-none-eabi-gcc` 不存在，`D:/Dev-Cpp/MinGW64` 是 x86 GCC，编不了 Cortex-M3）。

**排查/执行路径（按顺序）**：

```
① 装 ARM 工具链
   https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads
   选 Windows 的 arm-none-eabi，装完把 bin 加进 PATH

② 编译 MCU 固件
   tool\编译STM32固件.bat
   产物 mcu\build\spi2_dma_dac.hex

③ 重新综合并烧 FPGA
   tool\烧录FPGA.bat       （确保源码里含改过的 rtl/spi_mirror_tx.v）

④ 烧 MCU
   tool\烧录STM32.bat      （会自动优先用 mcu\build\spi2_dma_dac.hex）

⑤ 先验"DAC→音响"这一段，先别管 FPGA
   给 MCU 上电，应该听到一声 1 kHz 的"嘀"（0.25 s）
     响了  → DAC + RC 低通 + 功放 + 音响 全通，问题只可能在 SPI 输入
     不响  → 查 PA4/PA5 焊接、功放供电、喇叭、音量电位器
   ★ 如果连"嘀"都没有，先别动 FPGA 侧，一定是模拟链路的问题

⑥ 再验 SPI 输入
   启动 host 上位机 → 播放 → 看是否有声
   若"嘀"响但没音乐声：在 `spi2_dma_dac.c` 里观察 g_wr 是否在涨
     g_wr 不涨  → SPI 没收到字：查 GND 共地、PB13/PB12/PB15 接线、
                   FPGA 是否真的在发（用示波器看 SCK 有没有 24.4 kHz 的组）
     g_wr 在涨但没声 → 怀疑相位/帧同步：把 CS_PER_FRAME 改 0 试旧时序
  若声音是"咕噜咕噜的噪声"：几乎一定是 §3.4.1 第 0 条（时钟没配对），
     用示波器量 PA4 的更新率应为 24.4 kHz，若是 2.7 kHz 说明 clock_init 没生效
```

### 4.2 ⚠️ 阶段二的绝对分离精度无法量化

**状态**：修复了 2 个真实缺陷，链路不变量全部达标，但**绝对 SI-SDR 没有可信数字**。

**原因**：本机没有任何真实人声录音；合成信号会被 htdemucs 判进 `other`（实测 `vocals` 能量占比 0.0%），算出来的 SI-SDR 没有意义。

**需要的输入**：一段**带人声的音乐**（或者一段纯人声 + 一段纯伴奏的配对素材）。有了它就能走标准流程：

```
python -c "from host import local_ai; ..."   # 分离
# 用 mixture 与 ground-truth 算 SI-SDR / SDR / 能量比
```

如果暂时拿不到素材，可用的替代验收（都已通过）：
- 四轨重建恒等式 > 25 dB（实测 +39 dB）
- 能量守恒 1.005
- 分性别音轨的独立先验（4 kHz 硬声像伴奏不得出现在人声轨）

### 4.3 COM3 打不开

**状态**：`CreateFileW` 失败，`GetLastError=2`（ERROR_FILE_NOT_FOUND，设备不存在）。

`GetLastError=2` 与"端口被占用"（5）、"拒绝访问"（5）、"超时"（121）都不同 —— 它表示**系统里根本没有这个 COM 口**，不是权限或占用问题。

**排查路径**：

```
① 设备管理器 → 端口(COM 和 LPT) → 看实际有哪些 COM 口
   如果只有 COM4，说明单片机没被枚举成串口

② 单片机用的是 ST-Link，只有 VCP 才会出 COM 口
   部分 ST-Link 克隆版没有 VCP。查：
     tool\thirdparty\stlink_driver\stlink_VCP.inf  是否已安装
   或者改用 CH340/CP2102 转串口接单片机的 USART1

③ 如果设备管理器里有未知设备 / 黄色感叹号
   装 ST-Link 驱动：tool\安装STLink驱动.bat

④ 如果单片机的 USB 只做供电
   那它本来就没有 COM 口，属正常 —— 数据通路走的是 SPI，不经过串口
```

**补充**：按当前设计，单片机的数据通路是 **FPGA → SPI → STM32 → DAC**，**不需要串口**。COM3 打不开不影响主链路，只影响你想用串口打印调试统计的场景。
